## 0. 一句话定位

Transformer 是一个**基于自注意力的序列到序列（Seq2Seq）模型**，与基于 RNN 的 Seq2Seq 不同，它可以**并行计算**。

本章两条主线：
1. Transformer 的**结构**：编码器、解码器、编码器-解码器注意力
2. Transformer 的**训练过程**与 Seq2Seq 的训练技巧

> 📌 本文只到 7.3「Transformer 编码器」。

## 1. 序列到序列模型（7.1）

### 1.1 定义

输入和输出都是序列，长度关系有两种情况：
- 输入长度 = 输出长度
- 输出长度由**机器自己决定**

### 1.2 常见应用

| 应用 | 输入 | 输出 | 长度关系 |
|---|---|---|---|
| 语音识别 | 声音信号（长度 T） | 文字（长度 N） | N 由机器决定 |
| 机器翻译 | 一种语言的句子（N） | 另一种语言的句子（N'） | N' 由机器决定 |
| 语音翻译 | 声音信号 | 另一种语言的文字 | 长度由机器决定 |
| 语音合成（TTS） | 文字 | 声音信号 | 长度由机器决定 |
| 聊天机器人 | 一句话 | 回应 | 长度由机器决定 |
| 句法分析 | 一段文字 | 句法树（树 → 序列） | 树状结构转成序列 |
| 多标签分类 | 一篇文章 | 多个类别 | 类别数量由机器决定 |

> ❓ Q：既然把语音识别 + 机器翻译接起来就能做语音翻译，为什么还要专门做？
> A：世界上很多语言**没有文字**，无法做语音识别（如闽南语文字不普及）。直接做语音翻译可以绕过文字这一步。李宏毅实验室用 1500 小时乡土剧（闽南语语音 + 白话文字幕）训练闽南语→白话文模型。

### 1.3 闽南语语音翻译的启发

乡土剧字幕有噪声、音乐、字幕与声音对不齐等问题——**直接训练一个端到端模型，忽略这些问题**。这是工程上很务实的思路：先把粗糙数据丢进去，再迭代优化。

### 1.4 把"非翻译任务"也看成 Seq2Seq

很多任务都可以套上 Seq2Seq：
- **问答（QA）**：输入 = 文章 + 问题，输出 = 答案
- **自动摘要**：输入 = 长文，输出 = 摘要
- **情感分析**：输入 = 句子，输出 = 正面/负面
- **句法分析**：把句法树**转成序列**，就可以用 Seq2Seq（论文 *Grammar as a Foreign Language* 把语法当成另一种语言来"翻译"）
- **多标签分类**：一篇文章可属于多个类别，类别数量不固定 → 用 Seq2Seq，机器自己决定输出几个类别
- **目标检测**：论文 *End-to-End Object Detection with Transformers*（即 DETR）也用 Seq2Seq

### 1.5 Seq2Seq 的局限

> 📌 重要警示：Seq2Seq 像瑞士刀，什么都能做，但**不一定最好**。针对具体任务定制的模型往往表现更好。
>
> 例：Google Pixel 4 的语音识别用的是 **RNN-Transducer**（专为语音特性设计），而非 Seq2Seq。

## 2. Transformer 整体结构（7.2）

一般的 Seq2Seq 模型分两半：

```
输入序列 → [ 编码器 ] → 处理后的向量序列 → [ 解码器 ] → 输出序列
```

- **编码器（Encoder）**：处理输入序列，把结果"丢"给解码器
- **解码器（Decoder）**：根据编码器的输出决定输出序列

> Seq2Seq 起源很早：2014 年 9 月论文 *Sequence to Sequence Learning with Neural Networks* 就用 Seq2Seq 做翻译。Transformer 是 Seq2Seq 的**典型代表**。

本节只学编码器，解码器后续补。

## 3. Transformer 编码器（7.3）

### 3.1 功能与接口

- **输入**：一排向量
- **输出**：另一排向量（**长度相同**）

自注意力、RNN、CNN 都能"输入一排 → 输出一排"，Transformer 编码器选的是**自注意力**。

### 3.2 块（Block）的概念

编码器内部由多个**块（block）**串联：

```
输入向量序列 → [block 1] → [block 2] → ... → [block N] → 输出向量序列
```

⚠️ **关键**：一个 block ≠ 神经网络的一层。一个 block 内部做了好几件事。

### 3.3 一个 block 的内部结构

最朴素的版本（先不考虑残差和归一化）：

```
输入向量 → [ 自注意力 ] → 中间向量 → [ 全连接网络 ] → 输出向量
```

- 自注意力：考虑整个序列的信息
- 全连接网络：对每个向量单独处理

### 3.4 残差连接（Residual Connection）

原始 Transformer 在每个块里加了两次残差连接：

```
                ┌──── 残差：a + b ────┐
b（输入）→ [自注意力] → a ─────────────→ (+) → 层归一化 → 全连接输入
```

即：输出 = 自注意力输出 + 自注意力输入。目的：缓解深层网络梯度消失、信息丢失。

### 3.5 层归一化（Layer Normalization）

$$x'_i = \frac{x_i - m}{\sigma}$$

- $m$：输入向量的均值
- $\sigma$：输入向量的标准差

**层归一化 vs 批量归一化：**

| 维度 | 层归一化（LN） | 批量归一化（BN） |
|---|---|---|
| 计算维度 | **同一个样本**内不同特征维度 | **不同样本**的同一个特征维度 |
| 是否依赖 batch | ❌ 不依赖 | ✅ 依赖 |
| 适用场景 | 序列模型 / Transformer | CNN |

> ❓ Q：为什么 Transformer 用 LN 而不用 BN？
> A：论文 *PowerNorm: Rethinking Batch Normalization in Transformers* 解释了 BN 在 Transformer 里不如 LN，并提出了**能量归一化（Power Norm）**，性能跟 LN 差不多甚至更好。

### 3.6 一个 block 的完整流程（原始 Transformer）

```
                ┌──── 残差 ────┐               ┌──── 残差 ────┐
输入 → [自注意力] → (+) → [层归一化] → [前馈网络] → (+) → [层归一化] → 块输出
                          ↑                                    ↑
                       （这里的位置）                        （这里的位置）
```

更准确地说（按原文顺序）：
1. 自注意力 → 残差连接 → 层归一化
2. 全连接前馈网络 → 残差连接 → 层归一化

### 3.7 编码器整体结构（重复 N 次）

```
输入向量序列
   ↓
+ 位置编码（Positional Encoding）     ← 自注意力没有位置信息，要补
   ↓
┌─────────────────────────────────┐
│  多头自注意力                     │
│  + 残差连接 → 层归一化              │  ← 这个 block 重复 N 次
│  + 前馈网络（FFN）                 │
│  + 残差连接 → 层归一化              │
└─────────────────────────────────┘
   ↓
输出向量序列
```

> ⚠️ 原始 Transformer 的架构**不是最优的**。论文 *On Layer Normalization in the Transformer Architecture* 提出了另一种 LN 的位置设计，结果更好。这说明架构设计是可以质疑和改进的。

### 3.8 关键设计点回顾

| 设计 | 作用 | 备注 |
|---|---|---|
| 自注意力 | 考虑整个序列 | 可并行，是 Transformer 的核心 |
| 残差连接 | 缓解深层信息丢失 | `输出 = 子层输出 + 子层输入` |
| 层归一化 | 稳定训练 | 不依赖 batch，比 BN 更适合序列 |
| 前馈网络（FFN） | 对每个向量做非线性变换 | 自注意力后接 FFN 是标准组合 |
| 位置编码 | 注入位置信息 | 自注意力本身无序 |
| N 个 block 堆叠 | 增加模型容量 | N 是超参数 |

## 4. 我的理解 / 待探索

- **Transformer = 自注意力的堆叠 + 残差 + LN**，跟单看自注意力不一样：自注意力只解决"考虑整个序列"，残差 + LN 解决"能堆得很深还不崩"。两者结合才是 Transformer 能 work 的关键。
- **LN 选 LN 而非 BN** 的理由让我意识到：归一化方法的选择不是随便的，要看数据特点——序列长度可变、batch 内长度不一时，BN 会失效，LN 才稳。
- **"Seq2Seq 像瑞士刀但不一定最好"** 这个比喻很戳我。我之前默认"一个通用模型 = 好模型"，但作者反复强调**任务定制模型往往更好**（如 RNN-Transducer）。这跟我工作里"用通用脚手架省事 vs 针对场景优化"的取舍是一样的。
- **"原始 Transformer 不是最优"** 也让我警醒：论文里的架构不是圣经，可以质疑、可以改进（如 LN 位置变体）。这跟我工作里"别盲信 best practice"是一回事。
- **残差连接的位置** 我一开始没看明白，记下来：原始 Transformer 是「子层输出 + 子层输入 → LN」，不是「子层输出 + LN + 子层输入」。后续看 *On Layer Normalization...* 时重点对比这两种设计。
- **待学**：解码器（自回归、掩码注意力、编码器-解码器注意力）、训练技巧（teacher forcing、schedule sampling、beam search）、位置编码的具体公式。下一轮学习时续写到本笔记后半部分。
