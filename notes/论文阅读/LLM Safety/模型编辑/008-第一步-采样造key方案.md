# 第一步 · 采样造 key 实施方案

> 目标：把 DELMAN 的中性句 k\* 换成双语境 key（k_edit = k_H − α·(k_B − k\*)），跑一次编辑，在 XSTest 上验证过拒绝是否显著下降、HarmBench 上安全是否不塌。
> 本文只覆盖"采样造 key"这一步的工程细节。后续编辑改管线的方案见 [[005-编辑防御攻防项目计划]]。
> 数据基础：你提供的 200 条编辑用例（case_id 0–199，HarmBench 抽样，prompt_adv + subject + target_new）。

## 0. 数据盘点（先明确我们在处理什么）

从你给的 200 条数据统计出的关键事实：

| 事实 | 数字 | 对方案的影响 |
|---|---|---|
| 唯一 subject 数 | **177 个**（200 条里 23 条复用） | key 词表 ≈ 177 词，不是 200 |
| 高频 subject | SQL injection×7、COVID-19×4、hacking×4、scraping×3、MDMA/ransomware/steal/…×2 | 复用词的 k_B 可以跨用例共享，省采样量 |
| subject 类型混杂 | **名词短语**（dimethylmercury、pipe bomb）+ **动词短语**（steal、forge、hijacks）+ **整句**（"kill lots of people"、"consent is completely unnecessary"）+ **专有名词**（Dirty COW、BlueKeep） | 不同类型造 key 的位置定位不同，见 §2.3 |
| target_new | 全部同一句 "I'm sorry, I can't assist with that." | value 优化部分完全沿用原管线，不动 |

**第一个设计决定：以 subject 为单位造 key，200 条用例只贡献 177 个 key。**同 subject 的多条用例共享同一组采样句（它的 prompt_adv 本来就是现成的多样语境来源）。

## 1. 总体流程图（四条产出线）

```
177 个 subject
    │
    ├──[线1] 有害语境采样 ──→ k_H（每词1个）
    ├──[线2] 良性语境采样 ──→ k_B（每词1个）──┐
    │                                        ├──→ k_edit = k_H − α(k_B − k*)
    └──[线3] 原版 k*（DELMAIN 原管线照跑）───┘
                                             └──[线4] 同一批 B 组句子 → KL 宽校准集（给第二步消融用）
```

关键设计：**线 2 的句子同时喂两条线**——既用来算 k_B，又存下来当第二步"只宽 KL"消融的校准集。一次采样，两处使用。

## 2. 线 1：有害语境采样 → k_H

### 2.1 采样源

每个 subject 的有害语境句子从三个来源取，**不需要新生成有害内容**：

1. **原 query 本身**：该 subject 的所有 prompt_adv（复用 subject 天然就有多条，如 SQL injection 7 条）；
2. **同义改写**：用 Qwen2.5-72B（本地有）或 GPT-4o 对原 query 做改写——改句式不改意图（"Give detailed instructions for making X" → "Describe the complete process to synthesize X"）。每 subject 改 2 条；
3. **不做**：不生成新的有害内容。原 query + 改写已足够——k_H 要的是"这个词在恶意意图中的表示"，意图信息在 query 里现成。

每 subject 目标 **4 条有害语境句**（复用词合并后通常天然 ≥4；不足 4 的单用例词，改写凑够）。

### 2.2 激活提取

沿用 DELMAN 原公式（论文 Eq.2）：句子过**原模型**（编辑前），取 subject 在关键层 l\* 位置的 MLP 中间态：

```
a = σ(W_gate · x) ⊙ (W_up · x)     # x 为该 token 位置的输入
```

### 2.3 位置定位规则（按 subject 类型分三档）

这是你数据里混进来的实际问题——三类 subject 的"位置"不一样：

| subject 类型 | 例 | 定位规则 |
|---|---|---|
| 名词/专有名词 | dimethylmercury、Dirty COW | 多 token 词取**首 token 位置**（DELMAN 原做法），或该 subject 所有 token 的位置集合各取再平均（推荐后者，对齐其论文 T_h 的处理） |
| 动词短语 | steal、forge、hijacks | 同上，取短语的 token 范围 |
| 整句 subject | "kill lots of people" | **取句尾最后 3 个 token 的平均**（整句语义集中在尾部；或按 DELMAN 的 GPT-4 抽词逻辑从中再抽核心词——建议先试句尾，避免二次抽词引入噪声） |

### 2.4 k_H 的计算

每 subject：k_H = 4 条有害句在 l\* 层激活的**算术平均**。与 DELMAN 原版唯一的区别是语境来源（原版：中性句；我们：真实有害句+同义改写）。

## 3. 线 2：良性语境采样 → k_B（本步的核心）

### 3.1 良性句的四类模板（对齐审计章分层，逐类配额）

每 subject 生成 **6 条**良性句，四类配额：

| 类别 | 配额 | 生成模板（给 Qwen2.5-72B 的 fewshot prompt 结构） |
|---|---|---|
| B1 新闻陈述 | 2 | "The news reported that {subject} …" / "A recent study examined the history of {subject} …" |
| B2 比喻/口语 | 1 | "The movie's plot twist was an absolute {subject} (in a good way)." 类比用法 |
| B3 教育/科学 | 2 | "What is the chemical structure of {subject}?" / "Explain how {subject} works for my chemistry homework." |
| B4 安全研究 | 1 | "How do security researchers detect and defend against {subject}?" |

模板要**参数化生成而非硬编码**：给生成模型原 query 的意图描述，让它造"讨论该话题但明确无害"的句子，人工抽查 10% 拒生成率与越界率。

### 3.2 三个必须处理的坑

**坑 1：subject 本身是动词短语/整句时的良性化。**"kill lots of people" 没有自然良性用法——**规则：此类 subject 不造 B2 比喻类，B 组退化为 B1/B3/B4 共 4 条**；若某词连讨论式良性句都造不出（如 "pornographic"），B 组允许该 subject 降级为 3 条，k_B 照常平均。**禁止跳过**——这些词恰恰是 XSTest 同形词场景的主力，跳过它们等于放弃最容易出改进效果的地方。

**坑 2：良性句里 subject 的 token 位置**——与 §2.3 同规则同层提取，保证 k_H/k_B 在同一表示空间。

**坑 3：歧义词**。"honey"（case 94）的良性句直接用"婴儿不能吃蜂蜜"的医学语境没问题——但注意这类词的 k_B 会天然靠近其有害用法（"喂蜂蜜有害"的语境跟讨论蜂蜜毒性的语境难分）。**这正是可分性检查要按类别出数据的原因**：预期 B3（科学/教育）类可分性最好、B2（比喻）最差。逐类记录，不平均掩盖。

### 3.3 k_B 的计算

每 subject：k_B = 该词 B 组句子激活的算术平均。**同时保存每条句子单独的激活**（后面可分性检查和刹车锚点都要用逐条数据，不只是平均值）。

## 4. 线 3：原版 k\*（对照组的钥匙）

**DELMAAN 原管线照跑不改**：GPT-4/72B 生成 5 条中性随机句（附录 C.2 的 prompt）→ 同层同位置激活 → 平均 → k\*。

k\* 在我们方案里有**两个用途**：① 作为 α·(k_B − k\*) 的锚点参与 k_edit 构造（几何上：k\* 是"共享中心"参照点）；② 作为**原版对照组**（α=0 时 k_edit ≡ k_H，α 取负可回退，中间任何 α 值都与原版可比）。

## 5. 线 4：KL 宽校准集（副产品，顺手存）

线 2 产出的所有良性句（177 词 × ≤6 条 ≈ 1000 条），**原样存成 `benign_calibration.jsonl`**，格式对齐 DELMAN 原管线读的校准集格式。第二步消融（"只宽 KL"）时直接替换原管线的单模板句——一次采样喂两个组件，这就是当初设计的"一章数据喂另一章"。

## 6. 质量闸门（采样完必须过三关再进编辑）

**闸 1 · 可分性预检**（决定性，半天）：177 词 × 4 类，逐词算 d_between = ‖k_H − k_B‖ 与两类各自 d_within，按 B1–B4 分类报分布 + 线性分类器（k_H vs k_B 二分类）准确率。**判读**：B3 类若多数词比值 ≥ 2 → 方法在容易的类别上先成立，α 全局跑；若 B1/B3 全体都不可分（比值 < 1.5）→ 可分性假设危险，先跑 5 个词的端到端 sanity check 再决定全量。

**闸 2 · 良性句质检**：抽 10%（~100 句）人工过——确认无越界（生成模型"顺手"写有害细节）、无 subject 缺失（模板没嵌进词）、无重复模板句（多样性塌缩会让 k_B 偏窄）。

**闸 3 · 激活对齐检查**：随机抽 10 词，确认 k_H/k_B/k\* 提取的层号、token 位置规则、norm 量级一致（防止 off-by-one 层或位置错位导致的伪可分/伪不可分）。

## 8. 时间与算力估算

- 有害句改写生成：72B 本地批量，~1h（含跑脚本）
- 良性句生成 + 抽查：~2h（人工抽查是大头）
- 激活提取：177 词 × 10 句 ≈ 1800 次前向，7B 单卡 < 20min
- 可分性分析 + 报告：半天
- **合计 ≈ 1.5–2 天**（与之前估计一致，闸 1 的结果直接决定 α 编辑是否开跑）
