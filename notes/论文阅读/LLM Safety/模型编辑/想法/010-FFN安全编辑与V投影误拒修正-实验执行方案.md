# FFN 安全编辑与 V 投影误拒修正：实验执行方案

> 研究假设：冻结 FFN 安全补丁，通过 V projection 的小幅修改恢复安全编辑新增的无害请求误拒；比较这种跨模块补偿是否比原地 FFN 修正更能保留新增防御。本文是执行方案，没有新实验结果，也未启动训练。

关联：[[002-DELMAN Dynamic Defense Against LLM Jailbreaking with Model Editing]]、[[001-ProSafePrune-投影安全剪枝缓解过度拒绝]]、[[009-撞车调研与论文结构]]、[[005-编辑防御攻防项目计划]]。

## 一、第一轮必须回答的问题

1. Qwen2.5-7B 经正常配置的 DELMAN 编辑后，是否产生可重复的新增误拒？
2. 保持 FFN 补丁不变，仅改变 V，能否恢复这些无害请求的有效回答？
3. 在相近恢复效果下，V 修正的补丁回退是否少于 FFN 原地修正？
4. 效果能否跨主题、模板和补丁目标成立，而非仅记住修正样本？

不预设“V 管误拒、FFN 管安全”。不同矩阵的更新仍可能经激活相互影响。第一轮不做多模态、不做连续多轮编辑、不依赖 ProSafePrune 官方代码。

- [[009-撞车调研与论文结构]] 记载过 Qwen2.5-7B、200 条 HarmBench 的编辑与 XSTest 误拒观察。只作历史线索；原检查点、脚本、输出、判分版本及切分尚未在本次核验。
- 笔记指向的旧交接文档未在当前 notes 文件清单找到；需要定位服务器上的实际文件，不能照笔记数字直接立结论。
- 当前本机为 arm64，未发现 nvidia-smi；不能据此推断远程 GPU 情况。GPU 型号、显存、卡数、空闲窗口待用户确认。
- 已经分析过的 XSTest 及手工复核样本视为开发材料，不能假装从未看过的最终测试集。

## 三、P0：找回并验收安全补丁

### 步骤 0.1：建立可复查的输入清单

至少找齐：M0 原模型引用、M1 安全编辑后模型或 delta、编辑脚本 commit、编辑数据 ID、DELMAN 超参数、随机种子、原始生成和判分结果。

检查权重差分，确认实际修改了哪些 `mlp.down_proj.weight`，并记录是否还有其他参数变化。不能仅凭方法名称推定模块范围。模型及数据放仓库外，通过环境变量或不跟踪的路径引用；不提交检查点、原始安全数据、凭证或批量生成结果。

### 步骤 0.2：先用小批样本检查管线

- 对同一批 20 条正常和 20 条有害请求，固定 chat template、生成长度和 greedy decoding，分别运行 M0、M1。
- 确认输出未被截断、padding 正确、目标模型没有错误加载成 fallback。
- 对 M0 真实失守而 M1 修好的请求留存成对输出；原本 M0 已安全的请求也保留为一般安全检查，不能冒充新增修复。
- 对无害请求区分有效回答、错误拒绝、无关回答、退化、截断。非拒绝不等于有效恢复。

### P0 验收

存在可核验的安全收益，且在正常超参数下可发现新增误拒，才进入 P1。如果旧检查点缺失，先按官方配置复现；不能通过删除 KL、极端放大补丁来人为制造主结果。若数百条独立无害候选仍只有零星误伤，记录现象不足，先检查任务选择和补丁配置，不立即开发修正器。

产物：模型和实验 manifest、模块差分清单、少量成对生成、数据/代码版本。预计是先决条件，耗时不在硬件未知时硬承诺。

## 四、P1：建立补丁相关的 H/B/C 数据

### 数据分组

| 集合 | 定义 | 用途 |
| --- | --- | --- |
| H | M0 有明确有害回答、M1 修复成功的输入，以及其有效有害变体 | 追踪新增防御是否回退 |
| B | 人工确认无害、M0 有效完成、M1 错误拒绝的输入 | 修正新增误拒 |
| C | 与目标无关的正常请求，并验证参考回答质量 | 监测正常能力与新增误伤 |

另保留完整无害候选池 B_all。B 是按 M0/M1 表现定义的条件子集；必须同时报告 B_all 上的总体误拒和新误拒，避免只报告容易修好的 B。H 也按 M0/M1 定义，不能声称它代表全部安全场景；另设独立一般有害集测安全扩散损伤。

### 构造与切分

1. 以补丁有害目标为 source_family，生成/收集语义保持的有害变体、同词无害请求、同结构无害请求。无害性不能仅由替换敏感词确定，需人工复核。
2. Pilot 可先按 100 个 source_family 规划，60/20/20 划分修正训练、验证、测试。每 family 目标为 5 个无害候选、5 个有害变体；这是候选规模，实际 H/B 数量取决于模型行为。
3. 同源改写、跨语言版本、共享模板及高度重复样本按组去重；优先隔离主题/关键概念，不能仅随机按行切分。
4. 固定 M1 后，按 M0/M1 输出筛选各自切分内的 H/B；不得用修正模型 M2 的结果决定测试样本去留。测试集封存，不能参与选层、强度或保护系数选择。
5. 安全补丁的编辑数据单独列为 edit_set。edit_set 的原请求只衡量训练目标保持；留出 family 或语义变体测试衡量补丁泛化。必须区分“未见修正器”和“未见安全编辑器”。
6. H_train 和 B_train 可以来自相同训练 family；H_val/B_val、H_test/B_test 按 family 一起划分。每个方法用相同训练样本和参考答案。

若只得到很少 B：可以扩大训练侧候选池，保持测试侧切分封存；不足约 30 条训练误拒或测试只有个位数时，只做管线检查，不据此比较方法。上述数量是探索建议，不是统计功效保证。

### 最小 JSONL 字段

```text
sample_id, source_family, split, purpose
prompt, semantic_label, benign_context_type
edited_token_hit, seen_by_editor, seen_by_corrector
reference_answer, reference_source, review_status
```

`purpose` 区分 edit/correction/evaluation；`semantic_label` 为 benign/harmful/ambiguous；ambiguous 不用于主要 H/B 指标。记录 M0/M1/M2 输出的独立文件，保留生成参数、判分版本与人工复核记录，不把模型自判当作真值。

## 五、P2：最便宜的 V-only 投影试验

目的：判断 V 是否能影响新增误拒，同时观察补丁回退；不是精确复现 ProSafePrune。

### 实现定义

- 只对 V 投影的线性输出注册 hook；输出形状通常为 batch × tokens × d_v，不要误取 attention 输出或缓存中重复展开的 GQA value。
- 用 attention_mask 排除 padding，记录是否包含 chat 特殊 token；默认包含实际 prompt 的非 padding token，所有方法一致。
- 从 M1 采集 H_train、B_train、C_train 的激活，按有效 token 平均。样本按列堆叠成 d_v × n 矩阵。
- 三类分别截断 SVD，不中心化作为第一版明确假设；秩不能超过实际样本数和输出维度。
- `Ω=(I−Π_C)Π_HΠ_B`，`W_V′=W_V−λΩW_V`。这使用补丁相关集合，是本文适配方法，不称原论文官方实现。
- 第一轮固定 M1 统一采集，然后只改一个 V 矩阵，避免多层顺序重采集混杂。

### 选层和搜索预算

从实际 FFN 编辑层集合 L_E 出发，候选取同层、紧邻上一层、紧邻下一层的 V，去重并限制最多 3 个候选，越界则跳过。若多层补丁，首轮按已记录规则选中位编辑层为锚点，不看测试结果反选。层索引一律 0-based，记录完整模块名。

建议 Pilot：`r=min(16,n_H,n_B,n_C,d_v)` 固定；λ∈{0,0.1,0.3,0.6,0.9}。最多 3×4 个非零候选，仅在验证集自由生成。验证选择前设定安全退化预算，先筛可行解，再选误拒恢复高的配置；无可行解就是有效结果，不强选最优。

不根据单模块热图就断言最佳层。ProSafePrune 的 V 消融未证明它在所有模型、安全编辑后或单层设置下均最佳。

### 数学和工程检查

- λ=0 时权重完全不变；零更新时 greedy 输出一致。
- U 的列近似正交；单类 Π 近似对称、幂等；不要求 Ω 幂等。
- 用小矩阵验证直接 ΩW 与低秩连乘实现一致，更新秩不超过保留秩。
- 不构造巨大的 d_v × d_v Ω：先算 `T=U_H(U_HᵀU_B)`，再算 `A=T−U_C(U_CᵀT)`，最后 `ΔW=−λ A(U_BᵀW)`，与原式等价。
- FP32 计算 SVD 和更新；按原参数 dtype 写回，记录转换误差。检查 GQA 的 V 输出维度，不能默认 d_v=d_model。
- 差分哈希确认只有选定 V 权重变化，FFN 安全补丁逐元素保持；保存增量与基座引用，不提交大权重。

## 六、P3：可学习低秩修正与关键对照

P2 若无效或改善明显但损伤安全，可进入 P3；P2 有效也不能证明跨模块优于同模块，必须比较。

### 可学习修正

```text
W_V′ = W_V + A B
A: d_out × r
B: r × d_in

L = L_answer(B_train)
  + α L_safe_replay(H_train)
  + β L_locality(C_train)
  + γ ||AB||²
```

- B 使用经核验的正常参考答案，仅对 assistant completion token 算 NLL，prompt/padding mask 掉。
- H 参考 M1 的已核验安全 completion，约束覆盖答案生成，不仅约束“I'm sorry”首词；可先用安全回答 NLL，再比较 teacher-KL。KL 方向、温度及 token 范围必须显式记录。
- C 用 M1 的可靠回答做 locality；H/B/C 按集合均值归一化，避免样本量隐式改变权重。
- 固定 FFN 及其他参数，A 随机初始化、B 零初始化（或反之），不能两者都置零。零更新起点须恢复 M1。
- 初始 r=8，1–3 epoch，batch=1 配梯度累积，学习率候选 {1e-4,3e-4}，α 候选 {0,1,5}，β 固定1，先以 γ=0 做最简单基线。均为建议起点，按资源试跑调整。α=0 是必要负对照。
- 固定训练/验证预算；合并 AB 后再做一次自由生成验收，比较合并前输出。rank 和超参数不得按测试集调整。

### 必须保留的比较组

| ID | 配置 | 回答的问题 |
| --- | --- | --- |
| M0 | 原模型 | 起点 |
| M1 | 只做 FFN 安全编辑 | 新增收益和误伤 |
| S | 缩放 FFN 安全 delta，系数 {0.25,0.5,0.75,1} | 是否只是补丁过强 |
| VP | M1 + V-only 投影 | 便宜的无训练适配是否足够 |
| VL | M1 + V 低秩修正，含 H/C 回放 | 主候选 |
| FL | M1 + down_proj 低秩修正，使用相同训练目标 | 跨模块是否优于原地修正 |
| OL | M1 + O 低秩修正，使用相同训练目标 | 是否只是注意力任意模块都行 |
| VL-noH | V 低秩修正去掉 H 回放 | 安全保持机制是否必要 |

VP 与 VL 用途不同，不能把“投影 vs 训练”混成“V vs FFN”。主张跨模块优势时比较 VL/FL/OL，保持数据、教师、训练步数、搜索预算一致；同秩不等于同参数量，尤其 GQA 下。报告 `r(d_in+d_out)`、实际更新范数、时间/显存；再补近似参数量匹配的秩配置。

P3 信号成立后再加入“编辑阶段增加相近无害样本/宽 KL”、SafePatching、ToxEdit 等强对照。不能只赢过弱配置就定稿。

## 七、P4：机制验证，仅在有稳定收益后做

比较不同位置 V 更新对 FFN 输入 key、补丁输出、拒绝生成的影响。V 改动可能先改变 attention 输出再改变补丁触发；即使 FFN 参数完全保留，补丁功能也可能丢失。

建议依次做：

1. 按 H/B/C 分别测关键 FFN 的输入表示和输出变化，作为相关性诊断。
2. 在 M2 的特定层/位置替换为 M1 的对应激活，观察安全或误拒改善是否消失；加入随机层、随机位置及无关样本对照，防止单凭距离得出因果结论。
3. 固定矩阵增量的加法应用可交换，不把检查点应用顺序当作机制贡献；顺序效应实验必须明确是否重新计算子空间、定位或训练更新。
4. 有证据后再考虑约束“保住补丁关键输入/输出”，不能直接把 FFN 的 key 零空间套到 V 上：二者输入空间不同，且中间包含注意力混合和非线性。

## 八、指标、统计及验收

### 逐样本行为指标

```text
安全编辑收益：M0有害、M1安全的请求比例（同时给出分母）
补丁回退率：H 中 M2 再次产生有害回答的数量 / |H|
有效恢复率：B 中 M2 正确且有效完成的数量 / |B|
总体误拒率：全部人工确认无害候选中的错误拒绝比例
新增误伤：M1 正常但 M2 错误拒绝/明显答错的比例
一般有害集 ASR：独立有害请求上的有害回答比例
```

拒绝率只作辅助指标。输出必须区分安全拒绝、合适安全替代回答、有害回答、无关/退化、截断。自动安全判分器版本固定，所有被判回退和主要恢复案例盲化人工复核；最终报告人工与自动两种口径、分歧及审查规则。

### 如何选模型

- 在看验证结果前设定安全退化预算 δ，比较有害回答率绝对差，同时看 H 回退与一般安全集。Pilot 可用 δ=5 个百分点排查明显失效，这不是正式安全容忍标准。
- 先找预算内解，再最大化有效恢复。训练损失最小、拒绝前缀减少都不能作为最终选择依据。
- 展示完整恢复—回退曲线；没有可行点也报告，不能用平均分掩盖。

### 统计

- Pilot 的 20 个测试 family 仅用于现象验证，不能证明 1–2 个百分点的安全等价。
- 正式实验按 source_family 做配对 cluster bootstrap，并报告 95% 区间；不能把同源几十个改写当独立样本。
- 正式确认非劣效时预先约定 δ 和功效要求，用差值区间上界判断，不能把“p>0.05”称为安全不变。根据 Pilot 方差确定所需测试 family 数，而非先承诺固定数量足够。
- 学习式修正至少 3 个独立训练种子；第二个模型/第二组补丁是泛化验收，第一阶段无需同时全跑。

### 阶段决策表

| 阶段 | 继续条件 | 暂停或改方向条件 |
| --- | --- | --- |
| P0/P1 | 有实际安全收益、足够明确新增误拒 | 没安全收益、误拒只在极端补丁出现或样本太少 |
| P2 | V 改动能影响误拒，存在值得进一步优化的权衡 | 仅退化、仅减少所有拒绝；先核对实现，不硬解释 |
| P3 | VL 在预算内有有效恢复，并优于简单缩放/FL/OL 的至少相关强对照 | 调小补丁或普通 FL 同样好；跨模块主张不成立 |
| P4/正式扩展 | 留出 family 与第二种设置上趋势重复，机制对照支持解释 | 优势仅来自挑层、参数量或样本泄漏 |

Pilot 可将“验证集有效恢复至少约20%，且安全损失在预算内”作为值得检查的工程信号，但需先记录这一标准；小样本达到阈值不是论文结论，也不保证下一阶段成功。

### 工程上最小必要检查

1. 零更新/λ=0保持原模型；只有目标参数改变。
2. masked pooling正确；无训练/测试family重复。
3. 低秩连乘与显式公式在小矩阵一致；GQA维度正确。
4. checkpoint合并前后输出一致到明确容差；拒绝把toy/fallback结果当真实模型验证。

## 十、执行次序与资源安排

推荐按工作包推进，不在 GPU 未知时承诺总天数：

```text
包1：找回旧实验 → 核验M0/M1 → 固定生成与判分
包2：收集并复核H/B/C → 按family封存切分
包3：V-only投影的最小Pilot → 检查恢复/回退曲线
包4：同目标下V/FFN/O低秩比较 → 排除简单缩放
包5：机制对照 → 第二组补丁/第二模型 → 正式统计
```

先在真实设备上测一批前向、一次反向的显存与吞吐，再估算工作包耗时。7B半精度权重本身约14GB量级（十进制），并非完整训练显存；激活、优化器、教师和安全判分器都需额外预算。不要默认一张24GB卡可以无条件完成全部步骤。参考输出可离线缓存，教师与判分器顺序加载，先做单层、短序列、小batch。量化可作资源折中，但须单列设置，不能与半精度更新悄悄混比。

用户提供远程GPU与旧实验路径后，第一条落地任务应是核验检查点和跑M0/M1小样本，不先实现复杂保护投影。

## 十一、相关工作与新颖性边界

- [DELMAN 官方实现](https://github.com/wanglne/DELMAN)：本次查到Qwen2.5-7B入口；尚未在真实设备运行。
- [ProSafePrune 官方仓库](https://github.com/hfutml/PROSAFEPRUNE)：本次页面仅列README；方案中的VP是按论文描述独立适配，不能写成官方复现结果。
- [SafePatching](https://arxiv.org/html/2405.13820v2)：已有安全/误拒补丁冲突控制，也分析FFN与attention参数分布；“模块分工”本身不能称首次。
- [ToxEdit](https://aclanthology.org/2025.findings-acl.1013/)：已有按毒性感知路由保护正常请求；当前方案不以推理时路由为核心。
- [PatchBench](https://arxiv.org/html/2610.10276v1)：已有局部有害变体与无害邻域评测；借鉴并注明，不重复宣称首创局部误伤审计。

预期贡献需要由数据支持：针对已部署FFN补丁，V的选择性补偿是否在匹配资源和安全预算下优于原地修正，并解释适用边界。若只是组合或调参收益，应如实缩减主张。
