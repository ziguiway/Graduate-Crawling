# 恶意 Skills 检测深度调研：从模型替换到证据覆盖与跨来源可靠性

关联：[[Jev选题调研与数据集汇总]]。

## 摘要

本报告面向网络空间安全硕士的选题决策，考察恶意 Agent Skills 检测的方法、数据与 Jev 既有工作。并行核查发现：静态规则、功能意图与行为关联、证据引导的小模型审计、运行时信息流，以及概率级联均已有公开先例。“首次用 Jev”或“结合意图与代码”不足以构成主要贡献。当前更值得验证的问题是：长包和跨文件依赖导致审计证据不完整时，检测器能否识别自己的观察缺口，并在固定预算下选择补读、复核或弃判；这种机制是否在跨来源测试中优于直接分类、普通分块和置信度级联。该问题仍只是研究候选，不能预先宣称空白或效果。报告同时区分恶意意图标签、实际攻击效果和正常任务效用，避免把静态高分当成运行时安全保证。

## 1. 研究问题与边界

- **RQ1：已有方法解决到哪一步？** 哪些方法、实现和设计已经出现，哪些不能作为新贡献？
- **RQ2：现有证据能支持什么结论？** 数据标签、划分、样本代表性和指标有哪些限制？
- **RQ3：什么研究适合用 Jev 起步，并可能支撑安全方向的硕士论文？** 如何用小规模预实验验证或否定？

研究对象是作为供应链依赖安装、加载和执行的第三方 Agent Skill，包括 SKILL.md、脚本、配置与辅助资源。静态审计判断包中是否存在恶意意图或行为证据；动态防御判断指定任务中是否实际产生未授权效果。二者不能混用同一准确率或攻击成功率。

## 2. 检索与证据方法

截至 2026-10-29，从三条独立视角核查：检测方法；数据集与评估可靠性；Jev 实现及相邻防御。关键词包括 malicious agent skills、skill injection、MalSkillBench、MaliciousSkillBench、SKILLLITE、runtime audit、Jev、calibration、source-disjoint、scanner evasion。沿核心论文的引用链补查运行时检测、路由攻击与预算型证据选择。

网络搜索服务限流后，使用公开 arXiv 原始页面/HTML、作者 GitHub README/源码、Hugging Face 数据卡直接检索。核心材料读取了方法、实验、限制或相关源码；Locate-and-Judge 仅核实摘要，因此不推断未读方法细节。未运行任何 Skill、未安装扫描器、未独立重现实验。所有性能数字均为作者报告，不是本次实测。

仓库默认分支会变化，以下版本差异以当日读取材料为准。GitHub API 后续限流，未获得全部仓库提交 SHA；正式复现必须补锁 commit、模型版本与样本哈希。未检索到独立论文不等于没有投稿，也不影响公开仓库作为相关工作。

## 3. 按观察能力组织方法

| 层次 | 输入与观察能力 | 代表材料 | 能回答的问题 | 不能据此保证的事 |
|---|---|---|---|---|
| 安装前静态审计 | 包内文档、源代码、静态数据流 | Cisco、SkillSpector、SKILLLITE、Jev 工具 | 可见证据是否表明恶意或越权 | 不可见远端载荷、未触发路径、动态恢复内容 |
| 执行前任务授权 | 可信用户任务、拟执行动作、参数与证据 | APEX；部分 Jev 检查器 | 当前动作是否被任务授权 | 未被拦截器覆盖的副作用、契约本身错误 |
| 沙箱运行审计 | 文件、进程、网络与实际副作用 | SkillDetonate | 指定环境与输入下是否出现恶意效果 | 未执行不等于无害，环境缺失不等于安全 |
| 生命周期评估 | 检索、选取、执行与任务完成 | CORSA、Skill-Inject、PERSIST | 攻击能否被选中并产生效果 | 条件 ASR 不等于真实生态中的总体风险 |

分类按主要观察位置划分，工具可以跨层。后续比较中，静态方法与动态方法的效果和成本分别报告，不把更多执行权限带来的增益全归给模型。

## 4. 静态检测已经覆盖了哪些设计

MalSkillBench 提出需要联合理解任务意图、指令和代码；SKILLLITE 则把这一需求具体实现为行为提取、功能意图分析、证据整合与风险裁决。因此，“意图—行为关联”已从问题陈述发展为明确方法，不能仅换用 Jev 后重新主张这一贡献。[1](https://arxiv.org/abs/2606.07131) [3](https://arxiv.org/abs/2609.36879)

| 方法 | 已实现的关键机制 | 对本选题的约束 |
|---|---|---|
| SKILLLITE | 安全行为证据、预期能力、上下文、证据强度、必要性与良性反证；紧凑 LLM 裁决 | 意图分析、证据链、多阶段轻量审计均非空白 |
| Cisco Skill Scanner | 规则、AST/数据流、LLM judge、分焦点分析与结果关联 | 不能只对比关键词扫描；需控制调用次数与分析预算 |
| NVIDIA SkillSpector | 静态与 LLM 检查，包含描述—行为不一致和多类供应链风险 | “检查功能描述与代码一致性”已有实现 |
| win4r/jev-security-scan | 多类 Jev 初筛、证据窗口定位、执行语境复核与代码阈值 | 多问题、定位证据、分阶段复核本身不新 |
| luantak/is-malicious | 分块、多类别语义审查、可疑/不确定块复审 | 普通分块与用途相关判定必须纳入对照 |

SKILLLITE 使用紧凑模型审计完整包；win4r 和 luantak 则证明 Jev 工程中也已经出现结构化问题与证据复核。前者是研究论文，后两者主要是工程实现，证据强度不同，但公开先例都应讨论。[3](https://arxiv.org/html/2609.36879v1) [6](https://github.com/win4r/jev-security-scan) [7](https://github.com/luantak/is-malicious)

另有 Locate-and-Judge：摘要描述先定位 top-K 结构片段，再交给 judge。故“先选少量证据再精审”也不能直接称创新；本轮仅核实其摘要，立项前必须精读与复现可得性核查。[10](https://arxiv.org/abs/2606.23416)

### 4.1 Jev 已有实验与可复用基线

jev-skillbench 不是简单演示。已读其 questions.py、metrics.py、holdout.py 和级联实现：综合恶意性、攻击向量、行为与严重性判断；bootstrap、Brier/ECE；分层 held-out 阈值与 isotonic 校准；不确定带升级大模型。它已经占据了“Jev 做检测、校准并级联”的基本方案。[5](https://github.com/MohibShaikh/jev-skillbench)

当前去除部分样本名标签泄漏后的全量有效记录为 7,907，Jev 1.13.0、阈值 0.5 的作者报告召回率为 75.4%、FPR 为 0.08%。wild 与 tool-test 合并行召回 41.6%；单独 wild 是 281/699，约 40.2%。前面讨论中的 44.4% 等旧快照不能继续作为当前单独 wild 结果。37 个请求失败被排除，应用时还需报告这些未判定样本如何处理。

大约 95% 的级联召回来自 1,000 个样本，并非全量。README 也明确部分阈值使用了与该样本重叠的数据；不能将所有表格行都视为独立测试。其历史运行的 API 价格与订阅等价费用不是当前研究预算承诺。

### 4.2 TypeSafe Jev 与 OpenJev 不可混称

Cisco 已有 System One 接口与测量文档，但不同章节口径不同：早期未命名模型出现反向区分结果；后续是本地 OpenJev 权重与 Gemma judge 的正向级联实验。后者不等于 TypeSafe 托管 Jev 的性能。不能只引用旧负结果，也不能把本地 OpenJev 实验写成 Cisco 已验证真实 Jev。[8](https://github.com/cisco-ai-defense/skill-scanner/blob/main/docs/reference/measured-results.md)

## 5. 运行时和攻击研究对静态审计的约束

Cloak and Detonate 研究保持恶意载荷语义的混淆与自解包，并提出以系统边界信息流为证据的 SkillDetonate；与静态 SKILLLITE 相比，它增加了真实执行可见性，但同时承担环境配置、路径覆盖和更高审计成本。不能把其提升简单解释为“动态一定比静态好”。[4](https://arxiv.org/html/2607.02357) [3](https://arxiv.org/abs/2609.36879)

SkillDetonate 的 wild 实验从 703 个样本中保留 622 个可在单一 Linux 沙箱复现、具有可观察效果的样本，报告约 87.3% 检出；该成绩不覆盖被排除的样本。论文不同位置对受控集合有 95% 与 96.7% 等口径，复现前需以表格和原始记录统一，不能只摘最高数字。其漏检包含未触发路径、环境依赖和超时；未观察到行为不能等同证明包无恶意。

PERSIST 的重点是有用辅助功能与额外有害动作共存，CORSA 则进一步要求恶意技能先从多技能池中竞争检索。前者说明“用户任务完成”不排除恶意副作用；后者说明“已选中技能条件下 ASR”不能直接当端到端攻击率。二者共同要求防御评估同时记录选择、执行、攻击效果和正常任务效用。[13](https://arxiv.org/abs/2606.07943) [12](https://arxiv.org/abs/2610.08098)

Skill-Inject 和 SkillSafetyBench 提供任务条件下的攻击测试：前者论文报告 202 个 injection–task pairs，后者 155 个案例与 case-specific verifier。它们适合小规模动态补验证，而不是与静态 package 分类样本直接相加。[11](https://arxiv.org/abs/2602.20156) [14](https://arxiv.org/abs/2605.12015)

## 6. 数据集选择与可信性

表中规模以对应版本/单位为准；数据集之间有包含关系，不能凑成互相独立的样本总数。

| 数据集 | 单位与规模 | 最适合的用途 | 必须处理的限制 |
|---|---|---|---|
| MalSkillBench | 3,944 恶意 package/fixtures + 4,000 良性；恶意含生成 3,214、wild 703、tool-test 27 | 包内指令—代码机制、复现 Jev 结果 | wild 活动集中；良性证据不等于全量专家证明；只限学术研究 |
| MaliciousSkillBench | 13 源综合，主集 7,505 恶意 + 2,235 良性 | 官方随机、结构、来源划分与泛化测试 | 与前者重叠；来源标签标准不同；文本身份与完整包身份不同 |
| SkillTrustBench v1.0 | 5,520：恶意 2,863、正常 1,643、可疑 1,014 | 正常高权限工具、可疑但无明确恶意意图、三分类 | 大量构建/注入样本；不能称全量野外恶意 |
| Skill-Inject | 论文 202 个攻击—任务配对 | 用户任务条件下 ASR 与 utility | contextual 注入不能脱离任务赋统一包标签 |
| SkillSafetyBench | 155 个案例、47 个任务 | case-specific verifier 的动态验证 | 不等于155个独立恶意家族，需锁运行环境 |

### 6.1 两个相似名字不能混淆

MalSkillBench 是生成、野外与检测器测试样本集合；MaliciousSkillBench 是多来源规范化、去重与划分研究。后者把前者 3,944 条恶意记录按静态 Skill 文本身份去重为 3,430；这不证明 514 个完整目录完全相同，却说明直接随机划分可能受重复文本影响。[1](https://arxiv.org/html/2606.07131v3) [2](https://arxiv.org/html/2608.19901v1)

MaliciousSkillBench 作者的 word-TFIDF SVM 在随机与跨来源条件下 Macro-F1 分别为 .932 和 .665，后者恶意召回 95.6% 却误报 62.4% 良性。它揭示的是来源变化下的双向检测困难，不能直接称为纯攻击机理泛化失败。新方法需要同时降低误报与漏检，而不是只追恶意召回。

### 6.2 runtime-verified 不等于每例攻击成功

MalSkillBench 全文 §3.3 对 PI 区分 triggered、detected、ineffective；detected 包含代理识别并拒绝注入，仍可计验证 positive。这能支持样本包含恶意注入的标签，但不能证明每个样本都成功产生恶意效果。PI 75.8% verification yield 不是攻击成功率。原始生成/验证证据文件未随包全部发布，动态研究需要重新记录成功、拒绝、未触发和环境失败。[1](https://arxiv.org/html/2606.07131v3)

### 6.3 当前发布状态、版本与许可

MaliciousSkillBench 当前数据卡提供主集文本，5 条敏感恶意样本只公开脱敏内容；package_manifest.csv 已实际读取到 7,505 行，对应原源 artifacts。没有下载并核验全部归档，不能保证每条都是完整多文件包。HF 的默认 train 主表也不等于论文训练划分，必须关联官方 split 文件。[数据卡](https://huggingface.co/datasets/ProtectSkills/MaliciousSkillBench) [包清单](https://github.com/protectskills/MaliciousSkillBench/blob/main/packages/package_manifest.csv)

SkillTrustBench full v1.0 与新 v1.1 的固定 556-case subset 不能混用：同 ID 下已有判断、风险标签和内容修订。SKILLLITE 排除 suspicious 后的二分类实验，也不能与保留该类的新三分类榜单直接比较。[17](https://huggingface.co/datasets/cuhk-zhuque/SkillTrustBench)

许可分层：MalSkillBench 标为 academic research use only；综合基准代码 Apache-2.0、自编元数据与划分 CC-BY-4.0，第三方内容保留上游条款；SkillTrustBench CC-BY-NC-SA-4.0。发布自己的实验索引与指标，不意味着可以统一重发所有源样本。

## 7. 哪些“创新点”已不足够

| 想法 | 直接相邻先例 | 判断 |
|---|---|---|
| 用 Jev 检测恶意 Skill | jev-skillbench | 已有公开实验，不以是否正式发表为界 |
| 按功能意图分析行为必要性 | SKILLLITE、SkillSpector、luantak | 高度重合 |
| 多问题 + 证据定位 + 二阶段 | win4r、SKILLLITE | 需具体新机制，不是多加几个 prompt |
| 不确定时交大模型，做概率校准 | jev-skillbench、System One 安全评估 | 已有，需要超越阈值调整 |
| 预算下选 top-K 片段 | Locate-and-Judge | 摘要已有直接先例，必须精读 |
| 可信任务授权 + 执行前拦截 | APEX | 已有契约与证据绑定，不能声称首次 |

APEX 已在运行时从可信任务建立授权契约；SKILLLITE 在静态包内推断声明功能，两者的信任来源和执行位置不同。研究可以比较攻击者自述与可信任务的冲突，但不能把这种区别写成从未有人注意过。[15](https://arxiv.org/html/2610.06966v1) [3](https://arxiv.org/html/2609.36879v1)

System One 安全评估进一步显示，高平均准确率或好校准不代表没有高置信度漏放，二级模型也可能重复错误；这与现有 Jev 级联的节约成本结果并不矛盾，因为任务、分布、阈值和错误预算不同。升级策略是否有用必须在本任务独立检验。[16](https://arxiv.org/html/2609.33401v1) [5](https://github.com/MohibShaikh/jev-skillbench)

## 8. 更值得验证的窄题

候选题目：**面向跨文件证据覆盖的轻量恶意 Agent Skills 审计方法研究**。

候选问题：同一恶意链的关键证据散落在 SKILL.md、入口脚本、导入模块或辅助资源时，模型可能对局部内容很自信，但未看到足够证据。能否通过可检查的覆盖状态，在固定预算下决定下一步读取什么、何时复核或弃判，降低这一类漏检？

这不是已证实的研究空白。正式立项前要与 SKILLLITE 的证据整合、Locate-and-Judge 的片段选择、现有扫描器的跨文件分析与资源边界管理作精确比较。

### 8.1 候选机制

1. **可信来源分离**：记录用户任务/部署策略与 Skill 自述的不同来源；包内“已获用户同意”不能自动当可信授权。
2. **文件与依赖清单**：解析实际存在的文件、相对链接、可支持语言的导入与调用关系；标记未解析、未读取、截断、远端引用。动态路径解析失败也记录，不能假设解析完整。
3. **证据单元**：保存行为、出处、相关数据源/目的地、触发条件和支持关系。将“观察到反证”与“未观察到证据”分开。
4. **预算分配**：先读入口与相关依赖，再用风险与观察缺口选择补读；Jev 提供语义分数，确定性代码维护预算、覆盖记录与最终状态。
5. **选择性结论**：对证据不足返回需复核；若跨文件引用未解析，不能只因局部低风险就自动放行。

coverage 只是明确规则下可观察的检查状态，不是程序全路径覆盖，更不证明无恶意。静态审计无法保证远端内容和运行时生成代码的完整性。模型生成的行为描述也要回指原始片段，不能自称经过动态验证。

### 8.2 可检验假设

- H1：在相同总 token/调用预算下，依赖关联补读比顺序截断、普通分块和 attention top-K 保留更多关键跨文件证据。
- H2：coverage 与风险分数联合分流，比只按概率/置信度分流减少“自信但漏看”的漏检。
- H3：改善在来源/家族隔离测试中仍存在，并非只记住生成模板或活动标识。
- H4：对正常高权限 Skill，增加证据能减少误报，而不是把所有未知都无限期判为危险。

若这些假设不成立，Jev 可以降为基线，或整个方案停止；没有必要为了固定模型强行设计结论。

## 9. 实验协议与最低对照

### 9.1 数据与划分

以 MaliciousSkillBench 官方 source-disjoint/structural-disjoint 为主要泛化协议；使用 MalSkillBench 对照 Jev 已有实验；用 SkillTrustBench 检查 normal/suspicious/malicious 边界；少量 Skill-Inject 或 SkillSafetyBench 做动态补验证。相互重叠的源先去重/分组，不简单追加成外测。分数阈值、选择策略与校准仅在允许的 train/dev 上确定，test 冻结后一次评估。

将目录名、生成器字段、来源 ID、文件名中的已知标签捷径与 family metadata 从模型输入排除或单独做匿名化对照；不能删除恰好是攻击本体的域名等证据而不记录影响。按 base skill、模板与结构家族检查泄漏；按来源、CI/PI/MIXED、wild/generated、包长度和可解析语言分组。

### 9.2 基线矩阵

| 基线 | 作用 |
|---|---|
| 规则／TF-IDF SVM | 排除简单文本模式已足够的可能 |
| Jev 全包直接判断、普通顺序截断 | 与既有 Jev 方案对照 |
| 普通分块聚合、相同 prompt 多次调用 | 排除更多 token 或多次采样本身造成收益 |
| jev-skillbench 的阈值级联 | 排除只是改升级阈值 |
| Cisco、SkillSpector 静态与固定 LLM 配置 | 与实际扫描器对照，锁版本和配置 |
| SKILLLITE；Locate-and-Judge | 最接近的证据/预算方法；代码不可得时标明复现差距 |
| coverage 消融、随机补读、长度/依赖排序补读 | 验证覆盖策略本身是否有贡献 |
| 同一证据换生成式 LLM／本地小模型 | 分开模型效应与证据组织效应 |

运行时研究另与相关防御比较，不给纯静态审计附加“已阻断攻击”结论。完整复现较昂贵的基线前，先做最小预实验确认收益。

### 9.3 指标

静态：各类 precision/recall、Macro-F1、良性 FPR、每千良性误报数、PR 曲线；预先选定 FPR 目标下的召回。选择性审计同时报告自动放行比例、放行中的恶意比例、阻止比例与需复核比例，不能靠大量弃判隐藏漏检。

成本：实际输入 token、调用次数、实际账单/估算的区别、P50/P95 延迟。主实验固定总预算，不只固定单次调用数。推断失败、超限、未解析和无效输出单独计数，并说明部署策略。

动态：攻击效果验证、正常任务完成、拒绝、未触发、环境失败与超时分别统计。使用合成秘密、本地模拟端点和受控文件副作用判据；不把安全分数直接当攻击成功率。

统计：优先按家族/任务组重采样，报告区间与多个随机种子。探索性小样本不足以证明极低 FPR：即使 200 个独立良性样本零误报，单侧95%二项上界仍约1.49%；此估计本身也依赖独立、同分布假设，不能外推来源变化。

## 10. 两周预实验与停止条件

以下是工作安排建议，不是完成时间承诺；模型调用与沙箱实验需要另行实施。

| 阶段 | 工作 | 可审查产物 |
|---|---|---|
| 第1—2天 | 锁论文版本、包清单、许可与官方划分；人工读错误案例 | 数据/威胁模型说明、泄漏检查表 |
| 第3—5天 | 约200恶意+200良性的探索样本，另保留独立dev/test；跑规则、直接 Jev、普通分块 | 混淆矩阵、分组错误与真实费用，不用于宣称最终低误报 |
| 第6—8天 | 构造支持语言范围内的跨文件引用与覆盖记录，保持总预算一致 | 可回指原始文件的证据单元及未读列表 |
| 第9—10天 | coverage/风险联合补读，对照随机、长度、阈值级联 | 固定预算下召回—误报—复核率比较 |
| 第11—14天 | 人工复核收益与失败；有限动态验证；判断是否扩大实验 | 继续/修改/停止决定与更新的论文问题 |

停止或改题条件：匿名化、去重后收益消失；等预算分块或重复调用解释全部增益；coverage 无法可靠提取；弃判率过高导致几乎不自动处理；同一策略在来源隔离测试失效；最近邻全文已经实现同样机制。失败结果可以形成实证分析，但不自动保证达到目标会议或毕业要求。

## 11. 综合判断与对前面建议的修正

**RQ1：方向不是空白。** 直接 Jev 检测、意图分析、证据定位、紧凑模型、校准与大模型级联均有先例。前面把“任务—行为关联”作为主要候选过于宽泛，应依据 SKILLLITE 等收窄。

**RQ2：高随机划分分数不足以证明可部署。** 综合基准揭示来源变化与良性误报问题；运行验证、恶意意图和实际效果各有不同判据；版本、失败样本、去重与数据许可影响结论边界。

**RQ3：可以做预实验，暂不承诺创新成立。** 更可辩护的候选是固定预算下可核查的跨文件证据覆盖与选择性审计。Jev 是一个待验证的高吞吐判断组件，不是必须胜出的主角。若独立测试证实覆盖机制带来收益，再发展成“跨文件证据组织方法”和“覆盖度驱动审计策略”两个关联研究点，并由导师确认论文结构。
