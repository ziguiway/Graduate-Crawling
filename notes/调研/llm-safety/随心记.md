# 安全与可用性之间存在权衡

更严格的过滤器可能降低危险输出，但也可能：

    误拒绝正常请求；
    降低模型帮助性；
    增加延迟；
    降低工具调用或多轮对话能力。

因此，安全评测不能只看“拒绝了多少攻击”，还要看正常请求上的性能损失。论文把这一点纳入建议的评测报告中，例如同时报告延迟、吞吐和干净任务准确率。

1. 多模态安全 现有方法主要针对文本，对抗图像、音频操纵、跨模态 Prompt Injection 仍缺乏成熟方案。

2. Agent 和多智能体安全 当 LLM 可以调用工具、读写记忆并协调其他 Agent 后，风险会扩展到工具调用注入、记忆投毒和级联故障。

3. 可扩展的安全对齐 RLHF 和 Constitutional AI 在模型规模和任务复杂度继续增加时，人工监督可能难以扩展。

4. Guardrails 的形式化验证 当前 Guardrails 大多通过经验测试验证，尚缺少可以证明安全覆盖率和漏检率的形式化方法。

5. 跨语言安全 英语之外的低资源语言安全数据和基准较少，攻击者可能利用跨语言能力差异绕过安全机制。
