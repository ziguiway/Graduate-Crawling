## Q1：自注意力的矩阵实现，原代码哪里有 bug？

实现的是单头自注意力（不做多头），代码在 `code/Lhy_Machine_Learning/2021 ML/03 Self-Attention/self-attention.py`。

原代码踩的坑：

| 问题 | 原代码 | 修正后 |
|------|--------|--------|
| 拼写 | `attention_scroce` | `attention_score` |
| softmax 数值稳定性 | `np.exp(x)` 直接算，大数会溢出 | 先减最大值 `x - x_max` 再 exp |

关键约定（与 [[自注意力机制]] 第 4 节一致）：

- 输入 X 是**列向量堆叠**：`X = [a¹ a² ... aᴺ]`，形状 `(d_in, N)`，每列一个输入向量
- `A = Kᵀ @ Q` 得到 `(N, N)`，**列 j 是 qʲ 对所有 k 的分数**
- softmax **按列**做，每列和为 1
- 输出 O 形状 `(d_v, N)`，与输入等长

## Q2：softmax 为什么按列（axis=0）做？原代码到底错在哪？

### 数据摆放：列 = 一个向量

笔记第 4 节约定 `I = [a¹ a² a³ a⁴]`，4 个输入向量拼成矩阵的 4 列：

```
        a¹  a²  a³  a⁴
I  =  [  .   .   .   .   ]   ← 第 1 行（特征维度）
       [  .   .   .   .   ]
       [  .   .   .   .   ]
            ↑
         第 j 列 = 第 j 个输入向量 aʲ
```

所以 X 形状 `(d_in, N)`：行是特征维度，列是序列位置。

### 注意力分数矩阵 A 的含义

`A = Kᵀ @ Q`，形状 `(N, N)`：

```
        q¹   q²   q³   q⁴    ← 列对应 query
A  =  [ α₁₁  α₁₂  α₁₃  α₁₄ ]   ← 行 1: k¹ 与各 q 的分数
       [ α₂₁  α₂₂  α₂₃  α₂₄ ]   ← 行 2: k² 与各 q 的分数
       [ α₃₁  α₃₂  α₃₃  α₃₄ ]
       [ α₄₁  α₄₂  α₄₃  α₄₄ ]
```

**第 j 列 = qʲ 去问所有 k¹..kᴺ 得到的分数**。

### softmax 应该归一化谁？

笔记说："对 A 每一列做 softmax，使每列和为 1"。

算 bʲ 时要的是 qʲ 对所有 key 的分布：

$$
b^j = \sum_i \alpha'_{i,j}\, v^i
$$

`α'_{1,j}, α'_{2,j}, ..., α'_{N,j}` 是 qʲ 对 N 个 v 的权重，这 N 个数加起来必须等于 1（一个概率分布），加权和才有意义。

这 N 个数正是 A 的**第 j 列**。所以对**第 j 列**做 softmax。推广到所有 j → 每一列各算各的 → `axis=0`。

### 原代码错在哪

```python
def softmax(x):
    exp_x = np.exp(x)
    return exp_x / np.sum(exp_x)   # ← np.sum 无 axis 参数
```

`np.sum(二维数组)` 不给 axis 时，会把整个 `(N,N)` 矩阵**拍扁成一维**，求所有元素的总和。于是除出来的是：每个元素 / 整个矩阵 N×N 个元素之和。

结果是**整个矩阵所有元素加起来等于 1**，而不是每一列加起来等于 1。这相当于"N 个 query 共享一个全局概率分布"，语义完全错位——算 b² 时拿到的不是 q² 对 N 个 key 的分布，而是一堆被全局稀释过的数。

### 三种 axis 的对照

| 写法 | 归一化范围 | 每列和 | 语义 |
|------|-----------|--------|------|
| `np.sum(exp_x)`（无 axis） | 整个矩阵 | 远小于 1 | ❌ N 个 query 抢一个总概率 |
| `np.sum(exp_x, axis=0)` | 每列内部 | = 1 | ✅ 每个 query 独立有自己的分布 |
| `np.sum(exp_x, axis=1)` | 每行内部 | = 1 | ✅ 但语义反了：每个 key 对所有 query 的分布 |

`axis=1` 不是错，是**另一种语义**（"每个 key 被多少 query 关注"做归一化），但它对不上笔记这套"bʲ 由 qʲ 主导"的 Q-主视角约定。按笔记必须 `axis=0`。

### 一句话记忆

> A 的**列**对应一个 query 对所有 key 的分数；要算 bʲ 必须把**第 j 列**归一化成分布 → 所以 softmax 沿 `axis=0` 做每列内部归一化。

## Q3：numpy 的 axis=0 到底是行还是列？（反直觉）

### 关键认知翻转

numpy 的 axis 指的是"**沿哪个方向遍历**"，不是"对哪一维做"。

- `axis=0`：沿着**行方向**（第 0 轴，竖着往下走）遍历 → 每次取一**列**的元素聚在一起 → "对每列求和"
- `axis=1`：沿着**列方向**（第 1 轴，横着往右走）遍历 → 每次取一**行**的元素聚在一起 → "对每行求和"

### 验证小例子

```python
import numpy as np
a = np.array([[1, 2],
              [3, 4]])
#       列0  列1
# 行0 [ 1   2 ]
# 行1 [ 3   4 ]

np.sum(a, axis=0)   # → array([4, 6])   跨行求和 = 每列的和（列0: 1+3=4, 列1: 2+4=6）
np.sum(a, axis=1)   # → array([3, 7])   跨列求和 = 每行的和（行0: 1+2=3, 行1: 3+4=7）
```

### 记法

> **axis=k 的 sum 会"吃掉"第 k 轴**，结果剩下的就是其他轴。
> - `axis=0`：吃掉行轴 → 只剩列 → 每列一个值 = "每列求和"
> - `axis=1`：吃掉列轴 → 只剩行 → 每行一个值 = "每行求和"

### 口诀

> **axis=0 竖着走 → 每列一个值
> axis=1 横着走 → 每行一个值**

### 回到注意力

A 形状 `(N, N)`，列 j = qʲ 对所有 key 的分数。要对每列归一化 → `axis=0`。✅

## Q4：softmax 里的 keepdims 是干啥的？

接 Q3 那个"吃掉第 k 轴"的比喻：

> 默认 `np.sum(a, axis=0)` 会**吃掉**第 0 轴，二维 → 一维。
> `keepdims=True` 是说："吃可以，但别把那根轴抹掉，**留一个长度为 1 的占位**。"

### 例子对比

```python
a = np.array([[1, 2],
              [3, 4]])            # shape (2, 2) → 行轴=0, 列轴=1

np.sum(a, axis=0)                 # → array([4, 6])       shape (2,)   ← 行轴被吃掉，变成一维
np.sum(a, axis=0, keepdims=True)  # → array([[4, 6]])     shape (1, 2) ← 行轴保留但变 1
```

注意第二个结果多了一层方括号——就是那根长度为 1 的轴被保住了。

### 为什么 softmax 里非用不可？

```python
x_max = np.max(x, axis=axis, keepdims=True)         # (1, N)
exp_x = np.exp(x - x_max)                           # (N,N) - (1,N) → 广播成 (N,N)
return exp_x / np.sum(exp_x, axis=axis, keepdims=True)  # (N,N) / (1,N) → 广播成 (N,N)
```

**关键在广播（broadcasting）**：要"每列减去该列最大值" → 需要 max 的形状能跟 `(N, N)` 对齐做减法。

- **不开 keepdims**：`np.max(x, axis=0)` 得 `(N,)` 一维，广播时从末尾对齐 → 视作 `(1, N)`，沿行方向广播 = 每列各减各的。**碰巧 `axis=0` 时是对的**。
- **换 `axis=1` 时不开 keepdims**：`(N,)` 会沿**列方向**广播 → 错位。
- **开 `keepdims=True`**：得 `(1, N)` 或 `(N, 1)`，形状明确，不靠广播规则脑补。

开 keepdims 的好处：

1. **意图明确**：`(1, N)` 直接告诉你"沿 axis=0 归一化"，不用脑补广播方向。
2. **避免踩坑**：换轴时不会因为广播方向变了而出错。
3. **跨轴一致**：不管 axis 是 0、1 还是 -1，结果形状都可预测。写通用函数（如 `softmax(x, axis=-1)`）时几乎必须用。

### 记法

```python
a shape (2, 3)
np.max(a, axis=0)                  # shape (3,)     ← 轴 0 没了
np.max(a, axis=0, keepdims=True)   # shape (1, 3)   ← 轴 0 变成 1，没彻底没
np.max(a, axis=1, keepdims=True)   # shape (2, 1)   ← 轴 1 变成 1
```

> **不开 keepdims：被吃的轴彻底消失，维度降一**
> **开 keepdims=True：被吃的轴保留为 1，维度不变，便于广播对齐**

## Q5：axis 这个英文单词到底是啥意思？

### 日常含义

- 物理/几何：一根穿过物体中心的直线，物体围绕它旋转（如地球的自转轴 Earth's axis）。
- 抽象：事物的核心或中心线（如：争论的轴心点）。

### 在 NumPy / PyTorch / TensorFlow 中

axis 指的是数组的"**维度方向**"。把多维数组想象成多层表格，axis 告诉你**沿着哪个方向去操作数据**。

### 二维数组的直观图解

```python
import numpy as np
data = np.array([
    [1, 2, 3],   # 第 0 行
    [4, 5, 6]    # 第 1 行
])
```

| axis     | 方向         | 操作语义            | 结果                                                              |
| -------- | ---------- | --------------- | --------------------------------------------------------------- |
| `axis=0` | 沿行方向（垂直向下） | 跨行操作，把每一列压缩成一个值 | `np.sum(data, axis=0) = [1+4, 2+5, 3+6] = [5, 7, 9]`（按列求和，3 个数） |
| `axis=1` | 沿列方向（水平向右） | 跨列操作，把每一行压缩成一个值 | `np.sum(data, axis=1) = [1+2+3, 4+5+6] = [6, 15]`（按行求和，2 个数）    |

### 在 Softmax 中的含义

```python
# 形状: (3 个样本, 4 个类别)
logits = np.array([
    [2.0, 1.0, 0.1, 0.5],  # 样本1
    [0.0, 3.0, 1.0, 2.0],  # 样本2
    [1.0, 1.0, 1.0, 1.0]   # 样本3
])

# axis=1 表示对每个样本内部的 4 个类别做 softmax
probs = softmax_batch(logits, axis=1)
# 结果：每行概率之和 = 1.0，因为每个样本是一个独立的概率分布
```

**搞错 axis 会怎样？** 对 3×4 数据用 `axis=0` → 把不同样本的相同位置类别强行归一化 → 每个样本的概率之和不为 1 → 完全失去"分类概率"的意义。

### 快速记忆法则

| axis | 方向 | 结果 |
|------|------|------|
| `axis=0` | 沿行移动（垂直） | 消掉行，留下列数 |
| `axis=1` | 沿列移动（水平） | 消掉列，留下行数 |
| `axis=-1` | 最后一个维度（最内层） | 图像处理中常用，因为 channel 通常在最后 |

### 各框架默认值

| 框架 / 函数 | 默认 axis | 说明 |
|------------|----------|------|
| `np.sum()` | None（展平所有） | 不指定则计算全部元素总和 |
| `F.softmax()` (PyTorch) | 必须指定 | 没有默认值，防止出错 |
| `tf.nn.softmax()` (TF) | `axis=-1` | 默认对最后一个维度操作 |

> **一句话总结**：axis 就是告诉程序"沿着哪个方向走，把哪一层的数字拿来算"。

## Q6：怎么知道 axis=0/1/2/3 对应哪个方向？

**核心口诀：axis=N 就是"干掉"第 N 层括号。**

数组用 `[]` 层层嵌套表示维度，axis 的数字就是从外到内数**第几层括号**。

### 实战：看括号数轴

```python
import numpy as np
data = np.array([
    [  # 第 0 张图片（最外层括号的第 1 个元素）
        [1, 2, 3, 4],   # 第 0 行
        [5, 6, 7, 8],   # 第 1 行
        [9,10,11,12]    # 第 2 行
    ],
    [  # 第 1 张图片（最外层括号的第 2 个元素）
        [13,14,15,16],  # 第 0 行
        [17,18,19,20],  # 第 1 行
        [21,22,23,24]   # 第 2 行
    ]
])

print(data.shape)  # (2, 3, 4) → 2 张图，每张 3 行，每行 4 个像素
```

### 剥洋葱法：数括号定 axis

| axis | 括号层 | 含义 | shape 中位置 | sum 后谁被"干掉" | 结果形状 |
|------|--------|------|------------|------------------|---------|
| `axis=0` | 第 1 层（最外） | 图片数量（2 张） | `(2, 3, 4)` 中的 2 | 把 2 张图合成 1 张 → `[1+13, 2+14...]` | `(3, 4)` |
| `axis=1` | 第 2 层（中间） | 行数（每张 3 行） | `(2, 3, 4)` 中的 3 | 把 3 行压成 1 行 → 每张图 `[1+5+9, 2+6+10...]` | `(2, 4)` |
| `axis=2` | 第 3 层（最里） | 列数/特征（每行 4 个） | `(2, 3, 4)` 中的 4 | 把 4 列压成 1 列 → 每行 `[1+2+3+4, 5+6+7+8...]` | `(2, 3)` |

### 快速判断技巧（不用数括号）

- `axis=0` = "垂直往下走"（跨行）
- `axis=1` = "水平往右走"（跨列）
- `axis=2` = "纵深往里走"（跨通道/深度）

二维表格（行, 列）中：

- `axis=0` 是列方向（对列操作，保留列数）—— 往下走，把每列的数加起来
- `axis=1` 是行方向（对行操作，保留行数）—— 往右走，把每行的数加起来

### Softmax 的具体场景

数据形状通常是 `(batch, channel, H, W)` 或 `(batch, H, W, channel)`：

- `axis=1`：对通道做 softmax（如让每个像素的 RGB 三通道概率和为 1，常用于语义分割）
- `axis=-1`：对类别做 softmax（全连接层输出分类概率时最常用）

### 一行代码验证法（最推荐！）

不确定该写几时，别猜，直接试：

```python
import numpy as np

x = np.random.rand(2, 3, 4)
print("原始形状:", x.shape)
print("axis=0 后:", np.sum(x, axis=0).shape)  # (3, 4)  → 2 消失了
print("axis=1 后:", np.sum(x, axis=1).shape)  # (2, 4)  → 3 消失了
print("axis=2 后:", np.sum(x, axis=2).shape)  # (2, 3)  → 4 消失了
```

> **观察规律：axis 等于几，shape 对应位置的那个数字就被干掉了。**

### 速查表

| 你要做什么 | 该用哪个 axis |
|----------|--------------|
| 对每个样本内部的类别做归一化 | 类别所在维度（通常 `axis=-1`） |
| 对整个批次的同一个特征做归一化 | `axis=0` |
| 处理单张图片的 RGB 通道 | 若形状 `(H, W, C)`，用 `axis=-1`（或 `axis=2`） |
| 不确定时 | 打印 `x.shape`，看想让哪个数字消失，就选那个数字的索引 |

> **一句话记忆**：axis 就是"我想把哪一层的括号拆掉合并"。

## Q7：多头注意力怎么实现？比单头多了什么？

### 多头的本质

单头：一份 Q/K/V → 算分数 → 加权和。
多头：**同一组输入映射成 h 份 Q/K/V，各算各的注意力，最后拼起来再过一层线性变换**。每个头可以关注不同方面（有的学语法、有的学语义、有的看长距离依赖）。

### 五步拆解

```
1. 一次大投影：用一个大矩阵 W_Q (h*d_k, d_in) 一次算完所有头的 q
   —— 用一个大矩阵代替 h 个小矩阵，一次矩阵乘法搞定（工程优化）
2. reshape 拆头：(h*d_k, N) → (h, d_k, N)，不复制内存，只改 shape
3. 每个头各自做 scaled dot-product attention
4. 按 feature 维拼接 → (h*d_v, N)
5. 输出投影 W_O 压回模型维度 (d_model, N)
```

### 和单头的两个本质区别

1. **多了 W_O 输出投影** —— 多头各自学到的信息混合成最终输出
2. **加了 1/√d_k 缩放** —— 多头堆叠后数值会膨胀，不缩放 softmax 会饱和、梯度消失（单头 d_k 小可以不加，多头必须加）

### 为什么要"一次大投影"而不是循环 h 次

数学上等价，但一次矩阵乘法比 h 次小矩阵乘法高效得多（CPU/GPU 对大矩阵并行优化更好）。PyTorch `nn.MultiheadAttention` 内部也是这么做的。

### 维度约定（沿用列向量堆叠）

| 张量 | 形状 | 含义 |
|------|------|------|
| X | (d_in, N) | 输入序列，N 个列向量 |
| W_Q | (h*d_k, d_in) | 一次投影出所有头的 query |
| W_K | (h*d_k, d_in) | 同上，对应 key |
| W_V | (h*d_v, d_in) | 同上，对应 value |
| W_O | (d_model, h*d_v) | 输出投影，拼接后压回模型维度 |

### `d_model` 到底是什么

**一句话：`d_model` 就是输出向量 bʲ 的"行数"——也就是这个列向量的分量个数。**

在列向量堆叠约定下：

- 输入 X 形状 `(d_in, N)` —— 每个输入列向量 aʲ 有 `d_in` 个分量
- 输出 O 形状 `(d_model, N)` —— 每个输出列向量 bʲ 有 `d_model` 个分量

所以 `d_model` 不是某个抽象概念，就是**输出列向量的维度（行数）**。

**关键认知：`d_model` 不一定等于 `d_in`。** 注意力机制可以做维度变换：输入 4 维，输出可以是 8 维、2 维、或保持 4 维——完全由 `W_O` 的行数决定。

**Transformer 里的约定**：`d_model` 是贯穿全模型的恒定宽度，所有子层（注意力、前馈网络）出入同维，让残差连接 `x + Sublayer(x)` 能直接相加。例：BERT-base `d_model=768`，GPT-2 small `d_model=768`，GPT-2 medium `d_model=1024`。

**多头里的约定**：`d_model = h × d_v`，即模型宽度被均分给 h 个头。例：`d_model=512, h=8` → 每头 `d_v = d_k = 64`。这样总计算量跟单头 d_model 维注意力差不多，但每个头在子空间里学不同注意力模式。

### 形状流转图（d_model=4, h=2, d_v=2, d_in=4, N=4）

```
        输入层                  注意力层内部                   输出层
        ──────                  ──────────                    ──────

  X  (d_in, N) = (4, 4)      ┌──── h 个头并行 ────┐
       │                      │                     │
       │ W_V@X                │                     │
       ▼                      │                     │
  V_all (h*d_v, N) = (4, 4)   │  reshape 拆头        │
       │                      │      │               │
       │ reshape(h, d_v, N)    │      ▼               │
       ▼                      │  V_heads (h, d_v, N) │
  V_heads (2, 2, 4)           │  = (2, 2, 4)         │
       │                      │      │               │
       │ 逐头算注意力           │      │ 每头输出      │
       ▼                      │      ▼  (d_v, N)    │
  每头输出 (2, 4)              │  = (2, 4)            │
       │                      │      │               │
       │ 拼接 concat(axis=0)   │      ▼               │
       ▼                      │  concat (h*d_v, N)   │
  concat (4, 4)                │  = (4, 4)            │
       │                      │      │               │
       │ W_O@concat            │      │               │
       ▼                      └──────┼───────────────┘
  O (d_model, N) = (4, 4)                   ▲
                                            │
                          输出列向量 bʲ 的维度 = d_model = 4
                          ← 这就是"模型维度"= 输出向量的行数
```

**完整流转**：4 维输入 → 投影成 4 维 → 拆 2 个头（每头 2 维）→ 各自算注意力 → 拼回 4 维 → W_O 输出 4 维。

**输入维度 = 输出维度 = d_model**，这就是 Transformer 能堆叠多层的原因。

### 关键易错点：reshape 的切分顺序

`V_all.reshape(h, d_v, N)` 按 **C order（行优先）** 切分：

```
V_all 的 h*d_v 行按顺序排列：
  行 0,1,...,d_v-1  → V_heads[0]   （第 0 个头）
  行 d_v,...,2*d_v-1 → V_heads[1]  （第 1 个头）
  ...
```

**约定**：W_V 大矩阵的前 d_v 行对应第 0 个头，后 d_v 行对应第 1 个头。PyTorch 也这么做。
**踩坑**：如果切分顺序错了（比如你想按列切但用了行优先 reshape），结果会"数学上没错、语义上全错"——每个头拿到的不是自己该拿的特征。调试这种 bug 非常痛苦，养成习惯：reshape 后 print 一下中间形状，或用小例子验证切分对不对。

### 与后续章节的衔接

Transformer 7.4 解码器里的 **masked self-attention**（掩码注意力）就是在多头基础上加了因果掩码——生成第 t 个词时只能看到前 t 个词。掩码实现：把分数矩阵上三角设成 -∞，softmax 后这些位置权重自然变 0。

## Q8：numpy 的 reshape 是什么 API？切分顺序怎么定？

### 作用

**改变数组形状，但不改变数据本身**——把元素"重新排座位"，每个人还是原来那个人。

### 基本语法

```python
np.reshape(array, new_shape)   # 函数式
array.reshape(new_shape)       # 方法式（更常用）
```

### 总数必须匹配

6 个元素能 reshape 成 `(2,3)` / `(3,2)` / `(6,1)` / `(1,6)`，但不能 `(2,4)`（要 8 个元素）。

### -1 的魔法：自动推断

```python
a = np.arange(6)          # [0,1,2,3,4,5]
a.reshape(2, -1)         # 我只知道要 2 行，列数你算 → (2, 3)
a.reshape(-1)            # 全展平成一维 → (6,)
```

### 内存顺序：C order（行优先）

`reshape` 默认按 **C order**：**最右边的索引变化最快**。

```python
np.arange(6).reshape(2, 3)
# [[0, 1, 2],     ← 先填第 0 行，再填第 1 行
#  [3, 4, 5]]
```

### 回到多头里的 `V_all.reshape(h, d_v, N)`

原始形状 `(h*d_v, N)`，即 `(8, 4)`（h=2, d_v=4, N=4 时）。reshape 成 `(2, 4, 4)`：

```
原来：(8, 4)  —— 8 行（h*d_v 个特征），每行对应一个时间步
        ↓ reshape
现在：(2, 4, 4) —— 第 0 维是头编号，第 1 维是该头内的特征，第 2 维是时间步

V_heads[0]  → 第 0 个头的 V，形状 (4, 4)
V_heads[1]  → 第 1 个头的 V，形状 (4, 4)
```

切分方式（行优先）：

```
V_all 的 8 行按顺序排列：
  行 0,1,2,3  → V_heads[0]   （第 0 个头）
  行 4,5,6,7  → V_heads[1]   （第 1 个头）
```

**含义**：W_V 大矩阵的前 d_v 行对应第 0 个头，后 d_v 行对应第 1 个头。

### reshape vs transpose：常被混淆

- **reshape**：改形状，**不改元素顺序**
- **transpose**：改形状，**同时交换轴的顺序**

```python
a = np.arange(6).reshape(2, 3)
# [[0, 1, 2],
#  [3, 4, 5]]

a.reshape(3, 2)   # 元素顺序没变，只是重新分组
# [[0, 1],
#  [2, 3],
#  [4, 5]]

a.T              # 转置，行列交换，元素位置变了
# [[0, 3],
#  [1, 4],
#  [2, 5]]
```

多头里错用 transpose 会把头和时间步搞混，结果完全错。

### 速查表

| 用法 | 含义 |
|------|------|
| `a.reshape(m, n)` | 改成 (m, n)，总数必须对得上 |
| `a.reshape(-1)` | 展平成一维 |
| `a.reshape(m, -1)` | m 行，列数自动算 |
| `a.reshape(h, d, N)` | 三维，按行优先填充 |

> **一句话记忆**：reshape 是"换个角度看同一组数据"，不搬动元素，只重新分组。

## Q9：位置编码的原始论文公式是什么？怎么从公式到 numpy 代码？

### 问题来源

实现 `positional_encoding` 时，看到骨架代码里那一行 `np.exp(np.arange(0, d_model, 2) * -(np.log(10000.0) / d_model))` 完全看不懂——为什么要用 log、为什么有负号、`np.arange(0, d_model, 2)` 又是什么？公式长啥样？

### 原始论文公式（Vaswani 2017）

Attention Is All You Need 论文给出的位置编码公式：

$$
PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d_{model}}}\right)
$$

$$
PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{model}}}\right)
$$

### 变量含义

| 符号 | 含义 | 取值 |
|------|------|------|
| `pos` | token 在序列中的位置 | 0, 1, 2, ..., seq_len-1 |
| `i` | 维度的"对编号"（每对维度共用一个频率） | 0, 1, 2, ..., d_model/2-1 |
| `d_model` | 向量总维度 | 超参数 |
| `2i` | 偶数维索引用 sin | 0, 2, 4, ..., d_model-2 |
| `2i+1` | 奇数维索引用 cos | 1, 3, 5, ..., d_model-1 |

### 直觉

- 每个 token 的位置编码是一个 d_model 维向量
- 这 d_model 个维度**两两一对**，每一对是一个 (sin, cos) 组合，对应一种**频率**
- 低维（i 小）→ `10000^(2i/d_model)` 接近 1 → 频率高 → 波变化快 → 编码**局部位置**
- 高维（i 大）→ `10000^(2i/d_model)` 接近 10000 → 频率低 → 波变化慢 → 编码**全局位置**
- 每个 token 是这些不同频率波的叠加 → **唯一编码**该位置

### 为什么是 sin/cos 而不是单一函数

1. **周期性可外推**：sin/cos 是周期函数，序列超过训练长度时位置编码仍合理（不像可学习 PE 会 OOV）
2. **相对位置可学**：`PE(pos+k)` 可以表示成 `PE(pos)` 的线性组合（利用 sin/cos 的和角公式），模型容易学到"相对距离"这种平移不变的特征
3. **值域有界**：sin/cos 输出在 `[-1, 1]`，加到 embedding 上不会数值爆炸

### 从公式到代码的推导（5 步）

**第 1 步：处理分母 `10000^(2i/d_model)`**

公式里这个数在分母上，要算 `1/10000^x`。直接算 `10000**x` 数值会很大（i 大时溢出），改用 `exp(-log(10000) * x)` 更稳定——`exp` 输出有界（不会 inf），负号让结果落在 `(0, 1]`。

数学等价：`1/10000^x = e^(-log(10000) * x)`，两边取 log 就明白。

令：

$$
\text{div}_i = e^{-\log(10000) \cdot 2i / d_{model}}, \quad i = 0, 1, \ldots, d_{model}/2 - 1
$$

`div` 是个长度 `d_model/2` 的向量。

**第 2 步：构造位置向量 `pos`**

```python
pos = np.arange(seq_len)[None, :]  # (1, seq_len)
```

形状故意扩成 `(1, seq_len)` 而不是 `(seq_len,)`，是为了后面跟 `div[:, None]` 做广播。

**第 3 步：算 `pos * div_i`（外积）**

对每个 `(i, pos)` 组合算 `pos * div_i`，用广播一次性算完：

$$
M_{i, pos} = pos \cdot \text{div}_i = \frac{pos}{10000^{2i/d_{model}}}
$$

这就是 sin/cos 的参数。形状 `(d_model/2, seq_len)`。

代码里：`pos * div[:, None]` 通过广播把 `(1, seq_len)` 和 `(d_model/2, 1)` 拼成 `(d_model/2, seq_len)`。

**第 4 步：套 sin/cos，填进偶数行和奇数行**

$$
PE = \begin{bmatrix}
\sin(M_{0, :}) \\
\cos(M_{0, :}) \\
\sin(M_{1, :}) \\
\cos(M_{1, :}) \\
\vdots
\end{bmatrix}
$$

即 `pe[0::2, :]` 填 sin、`pe[1::2, :]` 填 cos。

**第 5 步：列向量堆叠约定下的形状**

论文公式按 `(pos, dim)` 写，但本笔记列向量堆叠约定下 token 向量形状 `(d_model, N)`，所以 PE 也得是 `(d_model, seq_len)`，索引相应调整：

- 论文：`PE[pos, 2i]` —— 第 1 维是位置，第 2 维是维度
- 本笔记：`PE[2i, pos]` —— 第 1 维是维度，第 2 维是位置

### 完整代码

```python
def positional_encoding(seq_len: int, d_model: int) -> np.ndarray:
    pe = np.zeros((d_model, seq_len))
    pos = np.arange(seq_len)[None, :]  # (1, seq_len)
    div = np.exp(np.arange(0, d_model, 2) * -(np.log(10000.0) / d_model))  # (d_model//2,)
    pe[0::2, :] = np.sin(pos * div[:, None])  # 偶数行
    pe[1::2, :] = np.cos(pos * div[:, None])  # 奇数行
    return pe
```

### 三个关键的 numpy 技巧

**1. `np.arange(0, d_model, 2)` —— 生成 2i 序列**

`np.arange(start, stop, step)` 从 start 按 step 生成序列，**不含 stop**。
`np.arange(0, 8, 2)` = `[0, 2, 4, 6]`，正好是 `2i` 的取值（i=0,1,2,3 时 2i=0,2,4,6）。
长度 `d_model // 2`。

**2. `div[:, None]` —— 把 1 维升成 2 维便于广播**

`div` 形状 `(d_model//2,)` 是一维。
`div[:, None]` 把它升成 `(d_model//2, 1)` 二维。
这样跟 `pos (1, seq_len)` 相乘时，广播规则让它们扩展成 `(d_model//2, seq_len)`——正好是 `M[i, pos]` 矩阵。

`[:, None]` 的等价写法是 `[:, np.newaxis]`，效果一样。

**3. `pe[0::2, :]` —— 切偶数行**

`pe[start:stop:step]` 是切片，`pe[0::2]` 表示"从第 0 行开始，步长 2，到末尾"——切出第 0, 2, 4, ... 行。
`pe[1::2]` 切出第 1, 3, 5, ... 行。
两个切片都是 `(d_model//2, seq_len)`，跟 sin/cos 结果同形，直接赋值。

### 为什么是 `10000` 这个数

原论文经验值，没特殊理由。`10000` 决定了"最低频率的波长"约等于 10000 个 token，覆盖大多数任务的最大序列长度。换成 1000 或 100000 都能跑，效果差异不大。

### 验证

位置 0 时 `sin(0)=0`、`cos(0)=1`，所以 `PE[:, 0]` 应该是 `[0, 1, 0, 1, ...]` 这种交替模式——位置 1 时 sin/cos 取非零值，与位置 0 不同。

### 一句话记忆

> 位置编码 = 不同频率的 sin/cos 波叠加。低维高频编码局部位置、高维低频编码全局位置。代码里 `np.exp` + 负号是为了数值稳定地算 `1/10000^x`，本质还是那个公式。

## Q10：多头注意力里的 `W_O` 是干什么的？单头为什么没有？

### 问题来源

实现 `multi_head_attention` 时，最后一步 `O = W_O @ concat` 让人困惑——Q/K/V 的投影矩阵 W_Q/W_K/W_V 笔记里讲了，但 `W_O` 这个"输出投影"笔记里没单独提，凭空多出来一个矩阵要学，它是干嘛的？

### 回答

**一句话：`W_O` 把 h 个头各自算出来的结果"拼接"后做一次线性变换，让模型学会怎么混合这些头的信息。**

### 为什么必须有这一步——拆开看

多头注意力做了三件事：

```
1. 投影：X → h 份 Q/K/V（每份用独立的 W_Q_i / W_K_i / W_V_i 投影）
2. 各算各的注意力：h 个头并行算出 h 个输出 b₁, b₂, ..., bₕ
3. 拼接 + 输出投影：concat(b₁, ..., bₕ) → W_O → 最终输出
```

第 3 步里的 `W_O` 就是输出投影。它做的事：

```
concat  形状 (h*d_v, N)    —— 把 h 个头的输出按特征维拼起来
   ↓
W_O     形状 (d_model, h*d_v)
   ↓ @
O       形状 (d_model, N)  —— 拼回模型统一维度
```

### 为什么必须有 W_O（不是可选的）

**1. 维度对齐**：h 个头各自输出 `(d_v, N)`，拼起来 `(h*d_v, N)`，但 Transformer 下一层（FFN、残差）需要 `(d_model, N)`。`W_O` 把拼接后的维度压回 `d_model`。

**2. 让头之间能"对话"**：没有 `W_O` 的话，每个头算完就独立结束了，模型没法学到"头 1 的结果 × 头 2 的结果该怎么组合"。`W_O` 是个线性层，让模型从数据里学出"该把哪些头的哪些维度怎么混"。

**3. 让多头 ≠ 单头**：如果你只有一个头 `h=1`、且 `W_O` 是单位矩阵，那多头退化成单头。有了 `W_O`（即使 `h=1`），多头还是多了"额外的一次线性变换"——这是有意义的容量增加。

### 严格说不是"多学一个"——是"必然需要的额外参数"

准确的对比：

| 组件 | 单头 | 多头 |
|------|------|------|
| Q 投影 | W_Q (d_k, d_in) | W_Q (h·d_k, d_in) —— h 倍大 |
| K 投影 | W_K (d_k, d_in) | W_K (h·d_k, d_in) —— h 倍大 |
| V 投影 | W_V (d_v, d_in) | W_V (h·d_v, d_in) —— h 倍大 |
| **输出投影 W_O** | **无** | W_O (d_model, h·d_v) |

所以相比单头，多头**多了一个** `W_O` 矩阵。

**单头时不需要 W_O，是因为只有一个头，输出形状直接就是 `(d_v, N)`，跟 `d_model` 对得上（约定 `d_v = d_model`）。**

多头时：
- h 个头各算各的 → 拼起来 `(h·d_v, N)`
- 但下游（FFN、残差、下一层）只认 `d_model`
- **必须有东西把 `h·d_v` 压回 `d_model`** → 这就是 `W_O`

所以 `W_O` 不是"为了多学东西"，是**"多头的输出维度不匹配下游需求"被迫引入的**。它顺便给了模型"混头"的能力（哪些头重要、该怎么组合），是顺带的福利。

### 跟论文公式对应

原论文多头注意力的定义里就包含 `W_O`（论文里写作 `W^O`）：

$$
\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h) W^O
$$

$$
\text{head}_i = \text{Attention}(Q W_i^Q, K W_i^K, V W_i^V)
$$

那个 `W^O` 就是 `W_O`。**论文里多头注意力的定义里就包含 `W_O`，不是额外加的**。

### 参数量对比（让你有感觉）

假设 `d_model = 512, d_k = d_v = 64, h = 8`：

| 组件 | 参数量 |
|------|--------|
| W_Q | 512 × 512 = 262144 |
| W_K | 512 × 512 = 262144 |
| W_V | 512 × 512 = 262144 |
| **W_O** | **512 × 512 = 262144** |

四份等量——所以"多了一份 W_O"在参数量上让注意力层多了 1/4 的参数（4 份 vs 3 份）。

但这是**性价比很高**的 1/4：它带来的好处是 h 个头能学不同模式（语法、语义、长距离等），模型容量大幅增加。这也是 Transformer 论文做多头实验的原因——多花 1/4 参数换多视角能力。

### 一句话记忆

> `W_O` 不是 Transformer 新引入的，是多头注意力本身的组件——**拼接 h 个头的输出 → 压回 d_model → 让模型学会混合多头的特征**。单头没有是因为只有一个头、维度天然对得上；多头有是因为拼接后维度对不上，被迫引入。参数量上 W_Q/W_K/W_V/W_O 四份等量。

## 附：最终实现（单头 + 多头）

```python
import numpy as np


def softmax(x: np.ndarray, axis: int = -1) -> np.ndarray:
    """数值稳定的 softmax，沿指定轴归一化使该轴和为 1。"""
    x_max = np.max(x, axis=axis, keepdims=True)
    exp_x = np.exp(x - x_max)
    return exp_x / np.sum(exp_x, axis=axis, keepdims=True)


def self_attention(X, W_Q, W_K, W_V):
    """单头自注意力（笔记 6.2 节矩阵乘法实现）。

    X: (d_in, N)  列向量堆叠 I = [a¹ ... aᴺ]
    W_Q/W_K: (d_k, d_in)，W_V: (d_v, d_in)
    返回 O: (d_v, N)，每列是 bʲ
    """
    Q = W_Q @ X
    K = W_K @ X
    V = W_V @ X

    attention_score = K.T @ Q              # (N, N)，列 j = qʲ 对所有 k 的分数
    attention_weight = softmax(attention_score, axis=0)  # 每列归一化
    output = (attention_weight @ V.T).T   # (d_v, N)
    return output


def multi_head_attention(X, W_Q, W_K, W_V, W_O, num_heads):
    """多头注意力（笔记 6.4 节）。

    X: (d_in, N)
    W_Q: (h*d_k, d_in)，W_K: (h*d_k, d_in)，W_V: (h*d_v, d_in)
    W_O: (d_model, h*d_v)
    返回 O: (d_model, N)
    """
    _, N = X.shape
    h = num_heads
    d_k = W_Q.shape[0] // h
    d_v = W_V.shape[0] // h

    # 1. 一次性算出所有头的 Q/K/V
    Q_all = W_Q @ X   # (h*d_k, N)
    K_all = W_K @ X   # (h*d_k, N)
    V_all = W_V @ X   # (h*d_v, N)

    # 2. 按 head 拆开 → (h, d_k, N) / (h, d_v, N)
    Q_heads = Q_all.reshape(h, d_k, N)
    K_heads = K_all.reshape(h, d_k, N)
    V_heads = V_all.reshape(h, d_v, N)

    # 3. 每个头各自做 scaled dot-product attention
    scale = 1.0 / np.sqrt(d_k)
    outputs = []
    for i in range(h):
        Q_i, K_i, V_i = Q_heads[i], K_heads[i], V_heads[i]
        scores = (K_i.T @ Q_i) * scale              # (N, N)
        weights = softmax(scores, axis=0)           # 每列归一化
        outputs.append((weights @ V_i.T).T)          # (d_v, N)

    # 4. 按 feature 维拼接 → (h*d_v, N)
    concat = np.concatenate(outputs, axis=0)

    # 5. 输出投影压回模型维度
    return W_O @ concat   # (d_model, N)
```

运行结果：单头输出 `(d_v, N)`、多头输出 `(d_model, N)`，每列注意力权重和均为 1。
