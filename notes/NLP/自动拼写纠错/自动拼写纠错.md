## 1. 这份作业在做什么？

这份作业实现了一个简化版的自动拼写纠错系统。它的核心思想是：

1. 从语料库中统计每个单词出现的次数和概率；
2. 对用户输入的错误单词生成一批编辑距离较近的候选词；
3. 用词表过滤掉不存在的候选词；
4. 用语言模型概率给候选词排序，返回最可能的几个。

整体流程如下：

这里的“纠错”不是直接猜一个答案，而是先生成候选集合，再用概率模型选择候选。这个分层思路很重要：**编辑操作负责召回可能答案，词频概率负责排序答案。**

## 2. 数据预处理与概率模型

### 2.1 从语料中得到单词列表

`process_data(file_name)` 的任务是读取文本文件，并把文本变成统一格式的单词列表：

```python
def process_data(file_name):
    words = []
    # 读取文件 -> 转小写 -> 用正则提取单词 -> 加入 words
    return words
```

这里有三个关键点：

- `lower()` 让 `The` 和 `the` 被视为同一个词；
- `re.findall(r'\w+', text)` 可以从一行文本中提取连续的单词字符；
- 返回的是列表，而不是集合，因为列表保留了语料中单词出现的次数。

### 2.2 统计词频

`get_count(word_l)` 返回一个字典：

```text
word_count_dict[word] = 这个词出现的次数
```

可以把它理解为一个计数器：遍历每个单词，如果它已经出现过就加一，否则从一开始计数。

### 2.3 把词频转换成概率

设语料中所有单词出现次数的总和为：

$$N = \sum_{w \in V} count(w)$$

则单词 $w$ 的概率为：

$$P(w) = \frac{count(w)}{N}$$

在这个作业里使用的是最简单的 unigram 模型：只考虑单词本身的出现频率，不考虑上下文。例如，`thee` 出现得越多，`P(thee)` 就越大。

## 3. 字符串编辑操作

作业把一个单词拆成左、右两部分：

```python
L, R = word[:i], word[i:]
```

例如单词 `cans` 的切分可以是：

```text
('', 'cans'), ('c', 'ans'), ('ca', 'ns'), ('can', 's')
```

切分的好处是：很多操作都可以统一写成“修改 L 和 R，再拼接起来”。这也是列表推导式在字符串处理中的典型用法。

### 3.1 删除 delete

删除位置 `i` 的字符，相当于保留 `L`，去掉 `R` 的第一个字符：

$$delete(L,R) = L + R[1:]$$

例如：

```text
cans -> ans, cns, cas, can
```

删除操作的切分通常遍历 `range(len(word))`。如果额外生成 `('cans', '')`，右侧没有字符可删除，需要排除它。

### 3.2 相邻字符交换 switch

交换相邻字符，例如：

```text
eta -> tea, eat
```

如果 `L` 的最后一个字符和 `R` 的第一个字符存在，就可以把它们调换：

$$switch(L,R) = L[:-1] + R[0] + L[-1] + R[1:]$$

这里要特别注意边界条件：`L` 不能为空，`R` 也不能为空，否则访问 `L[-1]` 或 `R[0]` 可能出错。

### 3.3 替换 replace

替换操作是把原字符换成 `a-z` 中的另一个字符：

$$replace(L,R,c) = L + c + R[1:]$$

例如对 `can` 替换第一个字符，会产生 `aan`、`ban`、`dan` 等候选。通常要排除替换后仍然等于原单词的情况，否则“替换”没有发生。

### 3.4 插入 insert

插入操作是在每个切分位置插入一个字母：

$$insert(L,R,c) = L + c + R$$

插入必须遍历 `range(len(word) + 1)`，因为最后一个位置也可以插入：

```text
at -> aat, bat, ..., ata, atb, ...
```

这是一个很容易写错的边界：

- 删除、替换通常遍历已有字符位置：`range(len(word))`；
- 插入遍历字符之间和两端的空隙：`range(len(word) + 1)`。

## 4. 组合编辑操作生成候选

### 4.1 一次编辑

`edit_one_letter(word)` 把四类编辑操作的结果合并起来：

```text
一次编辑候选 = 删除 ∪ 交换 ∪ 替换 ∪ 插入
```

返回集合 `set` 而不是列表，是因为不同操作可能得到重复结果。例如插入或替换时，多个位置可能生成同一个字符串。集合可以自动去重。

`allow_switches` 参数用于控制是否把相邻字符交换纳入候选。最小编辑距离的定义通常只包含插入、删除和替换，因此后面测试最小编辑距离时会关闭交换操作。

### 4.2 两次编辑

`edit_two_letters(word)` 的思路是：

1. 先生成原词的一次编辑集合；
2. 对一次编辑集合中的每个词，再生成一次编辑集合；
3. 把所有结果取并集。

$$E_2(w) = \bigcup_{u \in E_1(w)} E_1(u)$$

两次编辑的候选数量会快速膨胀，所以不能盲目生成后再全部排序；后续需要配合词表进行筛选。

### 4.3 用概率选择纠错结果

对输入词 `word`，理想的候选选择过程是：

```text
候选集合 = {word} ∪ (E1(word) ∩ vocab) ∪ (E2(word) ∩ vocab)
候选排序依据 = probs[candidate]
返回概率最高的 n 个词
```

这里包含两个实用技巧：

- **集合交集**：只保留真实出现在词表中的字符串；
- **短路求值**：可以优先使用编辑距离更近的候选，只有没有结果时再扩大到更远的候选。

作业示例中输入 `dys`，可以得到 `days`、`dye` 等候选，然后根据语料概率排序。实际实现时应注意使用函数参数 `n`，而不是把返回数量写死为 2。

## 5. 最小编辑距离与动态规划

### 5.1 什么是最小编辑距离？

最小编辑距离表示：把一个字符串 `source` 变成另一个字符串 `target`，最少需要多少代价。允许的操作是：

| 操作 | 含义 | 默认代价 |
|---|---|---:|
| insert | 插入一个字符 | 1 |
| delete | 删除一个字符 | 1 |
| replace | 替换一个字符 | 2 |

如果两个字符相同，就不需要替换，代价为 0。

### 5.2 状态定义

令：

$$D[i,j] = source[:i] 转换为 target[:j] 的最小代价$$

因此完整矩阵的大小是：

```text
(len(source) + 1) x (len(target) + 1)
```

多出来的第一行和第一列表示空字符串：

- 空字符串变成长度为 `j` 的目标前缀，需要连续插入 `j` 次；
- 长度为 `i` 的源前缀变成空字符串，需要连续删除 `i` 次。

### 5.3 状态转移

对每个 `D[i,j]`，有三种可能的最后一步：

1. 从 `D[i-1,j]` 删除 `source[i-1]`；
2. 从 `D[i,j-1]` 插入 `target[j-1]`；
3. 从 `D[i-1,j-1]` 匹配或替换最后一个字符。

因此：

$$D[i,j] = min\begin{cases}
D[i-1,j] + del\_cost \\
D[i,j-1] + ins\_cost \\
D[i-1,j-1] + r\_cost
\end{cases}$$

其中：

$$r\_cost = \begin{cases}0, & source[i-1] = target[j-1] \\ rep\_cost, & source[i-1] \ne target[j-1]\end{cases}$$

### 5.4 为什么动态规划有效？

直接枚举所有编辑序列会产生大量重复计算。动态规划利用了两个性质：

- **最优子结构**：完整字符串的最优解由前缀子问题的最优解组成；
- **重叠子问题**：不同路径会反复遇到相同的 `(i, j)` 前缀组合。

把每个子问题结果保存到矩阵中后，每个格子只计算一次，时间复杂度为：

$$O(|source| \times |target|)$$

空间复杂度也是：

$$O(|source| \times |target|)$$

如果只需要最终距离而不需要完整路径，可以进一步压缩为两行空间；如果还要恢复具体操作序列，就需要保留矩阵或额外的回溯信息。

## 6. 这份作业最容易出错的地方

### 6.1 空字符串边界

插入操作需要包含 `('', word)` 和 `(word, '')` 两端；删除和替换则要避免对空的右侧字符串访问字符。

### 6.2 列表和集合的职责不同

- 列表适合保留顺序、展示中间过程；
- 集合适合去重、做并集和交集；
- 概率字典适合给候选打分。

### 6.3 候选生成和候选排序不是一回事

编辑距离只能说明“形式上接近”，不能说明“它是一个真实且常用的词”。例如一个字符串可能只差一个字母，但根本不在词表中。因此要先用 `vocab` 过滤，再使用 `probs` 排序。

### 6.4 最小编辑距离不包含交换

作业前半部分把相邻交换作为一种候选生成操作，但后半部分的动态规划公式只包含插入、删除、替换。两部分概念相关，但不是完全相同的编辑定义，测试时要保持操作集合一致。

## 7. 我的理解 / 个人思考

这份作业把一个看起来很“智能”的自动纠错功能拆成了几个可以独立理解的小模块：先用统计方法知道哪些词常见，再用字符串操作找到“长得像”的词，最后用概率做选择。它让我意识到，很多 NLP 系统并不是一步直接得到答案，而是“候选生成 + 候选打分”的组合。

字符串操作部分看似只是 Python 练习，但 `L/R` 切分实际上提供了一种统一的抽象：删除、替换、插入和交换都可以看成对切分结果的局部修改。动态规划部分则把“所有可能的编辑路径”压缩成一个二维状态表，让我看到算法如何通过保存中间结果避免重复计算。

后续复习时，我想重点重新推一遍 `D[i,j]` 的三个来源，并尝试给矩阵增加回溯功能：不仅得到最小代价，还能回答“具体是先删、再插入，还是替换得到的”。这会把动态规划从“算一个数字”连接到“恢复一条最优路径”。
