## 核心知识点 1：把词性标注看成局部多分类

给定一句话：

```text
我 喜欢 我的 手机
```

现在只判断“手机”的词性。模型依次尝试所有候选词性：

```text
“手机”是 NN，得多少分？
“手机”是 NR，得多少分？
“手机”是 VV，得多少分？
“手机”是 JJ，得多少分？
……
```

最终选择分数最高的词性：

$$
t^*=\arg\max_{t\in T}\operatorname{Score}(S,i,t)
$$

这里得到的是**分数**，不是概率。

### 与 HMM 的区别

| 对比项 | HMM | 线性模型 |
|---|---|---|
| 模型类型 | 生成式模型 | 判别式模型 |
| 核心问题 | 某个词性以多大概率生成这个词 | 哪些特征支持当前词属于某个词性 |
| 输出依据 | 发射概率、转移概率 | 特征权重之和 |
| 是否考虑相邻预测词性 | 考虑 | 当前局部模型不考虑 |
| 是否能看上下文词语 | 能 | 能 |

“局部预测”不等于“不看上下文”。当前模型可以使用前一个词、后一个词等特征，只是不使用其他位置**预测出来的词性**。

## 核心知识点 2：特征模板、特征与特征空间

### 特征模板

特征模板规定模型想观察哪些信息，例如：

```text
02：候选词性 + 当前词
03：候选词性 + 前一个词
04：候选词性 + 后一个词
07：候选词性 + 当前词第一个字
08：候选词性 + 当前词最后一个字
14：候选词性 + 当前词前缀
15：候选词性 + 当前词后缀
```

模板只是“填空格式”，还没有代入具体句子。

### 具体特征

判断“手机”是否为 `NN` 时，模板会被实例化成：

```text
02|tag=NN|word=手机
03|tag=NN|prev_word=我的
04|tag=NN|next_word=<EOS>
07|tag=NN|first_char=手
08|tag=NN|last_char=机
```

可以这样记：

```text
特征模板 = 填空题格式
具体特征 = 填完后的答案
特征空间 = 训练集中出现过的所有答案
```

### 特征空间 E

扫描训练集，把所有带有正确词性的具体特征收集起来：

$$
E=\{e_0,e_1,\dots,e_{|E|-1}\}
$$

每个特征对应唯一编号：

```text
0  -> 02|tag=NR|word=戴相龙
1  -> 03|tag=NR|prev_word=<BOS>
2  -> 04|tag=NR|next_word=说
……
```

本次小数据集最终得到：

```text
|E| = 81113
```

对应代码：

```python
def build_feature_space(sentences: list[Sentence]) -> FeatureSpace:
    feature_to_id: FeatureSpace = {}

    for sentence in sentences:
        words = sentence["words"]
        gold_tags = sentence["tags"]

        for index, gold_tag in enumerate(gold_tags):
            feature_strings = extract_feature_strings(
                words, index, gold_tag
            )

            for feature in feature_strings:
                if feature not in feature_to_id:
                    feature_to_id[feature] = len(feature_to_id)

    return feature_to_id
```

## 核心知识点 3：稀疏特征向量

对于一个训练实例，理论上可以创建一个长度为 $|E|$ 的向量：

```text
[0, 0, 1, 0, 0, ..., 1, ..., 0]
```

但 81,113 个位置中，当前词通常只触发十几个特征，绝大多数位置都是 0。

因此不保存完整向量，只保存值为 1 的特征编号：

```text
完整向量：
[1, 1, 0, 0, 1, 0, 0, 0]

稀疏表示：
[0, 1, 4]
```

`[0, 1, 4]` 的含义是：

```text
第 0 个特征值为 1
第 1 个特征值为 1
第 4 个特征值为 1
其他位置全为 0
```

对应代码：

```python
def vectorize_features(
    words: list[str],
    index: int,
    tag: str,
    feature_to_id: FeatureSpace,
) -> list[int]:
    feature_strings = extract_feature_strings(words, index, tag)

    return [
        feature_to_id[feature]
        for feature in feature_strings
        if feature in feature_to_id
    ]
```

> [!important] 二值特征要去重
> 课件中的特征向量是 0/1 向量。同一个字符串特征即使被重复触发，在向量中也只能取值 1，因此特征抽取结束后使用 `dict.fromkeys(features)` 按出现顺序去重。

## 核心知识点 4：点乘在代码里为什么变成了求和

课件中的打分公式：

$$
\operatorname{Score}(S,i,t)=w\cdot f(S,i,t)
$$

其中：

- $w$：长度为 $|E|$ 的权重向量
- $f(S,i,t)$：长度为 $|E|$ 的 0/1 特征向量

假设：

```text
w           = [3, 2, 1, -2, -1, 0]
f(S,i,NN)   = [1, 1, 1,  0,  0, 0]
```

点乘：

```text
3*1 + 2*1 + 1*1 + (-2)*0 + (-1)*0 + 0*0
= 3 + 2 + 1
= 6
```

由于稀疏表示只保存特征值为 1 的位置，所以代码不需要处理所有乘以 0 的项：

```python
def dot_product(feature_ids: list[int], weights: Weights) -> float:
    return sum(weights[feature_id] for feature_id in feature_ids)
```

因此：

```text
数学中的向量点乘
= 找到所有值为 1 的特征位置
+ 把这些位置对应的权重加起来
```

### 公式与代码的完整对应

| 课件符号 | 代码对象 |
|---|---|
| 句子 $S$ | `words` |
| 位置 $i$ | `index` |
| 候选词性 $t$ | `tag` |
| 特征空间 $E$ | `feature_to_id` |
| 特征向量 $f(S,i,t)$ | `feature_ids` |
| 权重向量 $w$ | `weights` |
| $w\cdot f(S,i,t)$ | `dot_product()` |
| $\arg\max$ | `predict_tag()` 中的最高分比较 |

## 核心知识点 5：预测过程

预测公式：

$$
t^*=\arg\max_{t\in T}w\cdot f(S,i,t)
$$

代码做的事情是：

```text
尝试第一个词性，记录它的分数
    ↓
依次尝试其余词性
    ↓
如果当前分数更高，就替换最佳答案
    ↓
返回最高分词性
```

关键代码：

```python
def predict_tag(
    words: list[str],
    index: int,
    tag_set: list[str],
    feature_to_id: FeatureSpace,
    weights: Weights,
) -> tuple[str, list[int]]:
    best_tag = tag_set[0]
    best_feature_ids = vectorize_features(
        words, index, best_tag, feature_to_id
    )
    best_score = dot_product(best_feature_ids, weights)

    for tag in tag_set[1:]:
        feature_ids = vectorize_features(
            words, index, tag, feature_to_id
        )
        score = dot_product(feature_ids, weights)

        if score > best_score:
            best_tag = tag
            best_feature_ids = feature_ids
            best_score = score

    return best_tag, best_feature_ids
```

训练刚开始时，所有权重都是 0，所有词性分数相同。代码使用排序后第一个词性作为平局结果，第一次预测通常会出错，然后由错误触发第一次更新。

## 核心知识点 6：Perceptron 如何学习

预测错误时，更新公式为：

$$
w_{k+1}
=w_k
+f(S,i,y_i)
-f(S,i,t^*)
$$

其中：

- $y_i$：人工标注的正确词性
- $t^*$：模型预测的错误词性

直觉：

```text
正确词性的所有激活特征：权重加 1
错误词性的所有激活特征：权重减 1
预测正确：不更新
```

对应代码：

```python
def perceptron_update(
    gold_feature_ids: list[int],
    predicted_feature_ids: list[int],
    weights: Weights,
) -> None:
    for feature_id in gold_feature_ids:
        weights[feature_id] += 1.0

    for feature_id in predicted_feature_ids:
        weights[feature_id] -= 1.0
```

例如：

```text
正确答案：NR
错误预测：NN
```

更新以后：

```text
NR 相关证据变强
NN 相关证据变弱
```

下次遇到相似词语或上下文时，模型就更容易选择 `NR`。

### 在线学习

模型每处理一个词就立即预测和更新，下一个词使用的是刚刚更新后的权重：

```text
处理词 1 → 更新 w
处理词 2 → 使用新的 w → 再更新
处理词 3 → 使用更新后的 w → 再更新
```

这就是 Online Training。

## 核心知识点 7：三个暂未实现的优化

### Averaged Perceptron

普通 Perceptron 最终直接使用最后一次更新后的 $w$。但训练过程中的权重会来回波动，最后一步不一定是泛化最好的状态。

平均感知器使用训练过程中权重的平均值：

$$
\bar{w}=\frac{1}{K}\sum_{k=1}^{K}w_k
$$

平均以后可以抵消部分偶然波动，通常更稳定。

本次实验中，开发集准确率在第 3 轮达到最高点，之后下降，正好说明最后的普通权重不一定最好。

### 累积权重 v 的延迟更新

直接计算平均权重，需要每一步都遍历整个特征空间：

```text
v = v + w
```

但一次错误只会修改少量特征。对于长时间不变化的权重，可以记录：

```text
当前权重
最后更新时间
```

等它再次变化时，一次性补上这段时间对 $v$ 的贡献：

```text
累计贡献 = 当前权重 * 保持不变的步数
```

这相当于把“每一步记账”改成“下次变化时一次结账”。

### partial feature

朴素版本对每个候选词性都重新生成完整字符串：

```text
NN + 当前词是手机
VV + 当前词是手机
JJ + 当前词是手机
```

其中“当前词是手机”被重复构造。partial feature 先抽取与词性无关的部分：

```text
当前词是手机
前一个词是我的
最后一个字是机
```

然后利用词性对应的 offset 得到完整特征编号：

```text
完整特征编号
= tag_id * partial_feature_count
+ partial_feature_id
```

partial feature 不改变模型，只减少重复的字符串构造。

## 我踩过的坑

### 坑 1：能运行的代码不一定和课件公式对应

第一版直接使用“特征字符串 → 权重”的字典，分数也是查询字符串后求和。程序能正常训练，但代码中看不到课件里的特征空间 $E$、特征向量 $f$ 和权重向量 $w$，导致我无法把“点乘”与实现联系起来。

后来显式加入：

```text
feature_to_id      -> 特征空间 E
feature_ids        -> 稀疏特征向量 f
weights            -> 权重向量 w
dot_product()      -> w 与 f 的点乘
```

代码才真正和课件建立起一一对应。

> [!lesson] 一句话记忆
> 程序跑通只是第一关；能把公式中的每个对象在代码里找到，才说明实现真正受自己控制。

### 坑 2：稀疏点乘看起来不像点乘

完整点乘包含大量“权重乘以 0”的项。稀疏实现只保存特征值为 1 的位置，所以点乘在代码里变成：

```python
sum(weights[feature_id] for feature_id in feature_ids)
```

不是没有点乘，而是省略了所有结果为 0 的乘法。

> [!lesson] 一句话记忆
> 稀疏向量只记录非零位置，因此与 0/1 特征向量的点乘就是“激活位置的权重求和”。

### 坑 3：列表中的重复特征会破坏 0/1 假设

如果同一个字符串特征因重复汉字被加入多次，直接对列表求和会把它累计多次，相当于特征值大于 1。

解决方法：

```python
return list(dict.fromkeys(features))
```

按出现顺序去重，使每个特征在当前实例中最多出现一次。

> [!lesson] 一句话记忆
> 课件说特征是二值的，实现时就必须保证同一特征不会被重复计数。

### 坑 4：句子边界不能直接取尖括号字符

如果把句首词写成 `<BOS>` 后再取最后一个字符，会错误得到 `>`。因此词边界和字符边界需要分别表示：

```text
前一个词不存在：<BOS>
前一个词末字不存在：<BOS_CHAR>
后一个词不存在：<EOS>
后一个词首字不存在：<EOS_CHAR>
```

> [!lesson] 一句话记忆
> 特殊标记是一个整体语义，不应再把它当成普通字符串随意切字符。

## 我的理解

线性词性标注模型的本质，是把人工认为有用的语言线索变成一组稀疏特征。每个特征都有一个可以学习的权重；判断一个词是否属于某个词性时，只要把当前被触发的特征权重加起来，就得到了这个词性的分数。所谓“权重向量与特征向量点乘”，在稀疏实现里就是“找到值为 1 的位置，再把对应权重求和”。

### 用权重矩阵理解整个模型

我最初的理解是：模型维护了一个具有很多维度的“特征矩阵”，这些维度可以描述一个词的特征；训练负责得到一个通用的矩阵，推理时让当前词对应的向量与它点乘，再遍历所有词性，选择分数最高的那个。

这个整体流程是对的，但更准确的说法是：**模型维护的是“词性 × 特征”的权重矩阵，而不是由训练决定特征本身。**

- 特征模板提前规定观察哪些维度，例如当前词、前后词、首字、尾字、前缀和后缀。
- 当前词及其上下文决定哪些特征被激活，形成稀疏特征向量 $x$。
- 训练过程学习每个“词性—特征”组合的权重，得到权重矩阵 $W$。
- 推理时，让每个词性对应的一行权重与 $x$ 点乘，得到所有词性的分数，再取最大值。

可以写成：

$$
\text{scores}=Wx
$$

$$
t^*=\arg\max_t \text{scores}_t
$$

如果把矩阵画出来：

| 特征 | NN 权重 | VV 权重 | JJ 权重 |
|---|---:|---:|---:|
| 当前词=手机 | 3 | -2 | 0 |
| 前一个词=我的 | 2 | -1 | 1 |
| 最后一个字=机 | 1 | 0 | 0 |

当前样本触发这三个特征时：

```text
x = [1, 1, 1]

NN 分数 = 3*1 + 2*1 + 1*1 = 6
VV 分数 = -2*1 + -1*1 + 0*1 = -3
JJ 分数 = 0*1 + 1*1 + 0*1 = 1

最终预测 = NN
```

当前代码把候选词性直接拼进完整特征，再把这个二维权重矩阵展平成一维权重向量 `w`；两种表示在数学上是等价的。使用 partial feature 和 offset 后，“每个词性占矩阵一行”的结构会在代码中表现得更加明显。

> [!note] “通用”的范围
> 训练得到的权重只是在当前特征模板、词性集合和训练数据范围内具有泛化能力，不是对所有语言和任务都通用。更换语言、标签集合或特征模板后，通常需要重新建立特征空间并训练。

### 特征空间和特征向量分别属于谁

我进一步把两者的关系理解为：

```text
特征空间：对应整个训练数据集，是模型中所有样本共用的坐标系统
特征向量：对应一个具体的预测情况，表示这次在坐标系统中激活了哪些位置
```

更严格地说，特征向量不只是对应某个孤立的词，而是对应：

```text
当前句子 S
+ 当前词的位置 i
+ 正在尝试的候选词性 t
```

也就是 $f(S,i,t)$。

例如，同样是“手机”：

```text
我的 手机
维修 手机
```

两个位置都会触发“当前词是手机”，但分别会触发“前一个词是我的”和“前一个词是维修”，因此特征向量并不完全相同。

在同一句“我的 手机”中，尝试 `NN` 和尝试 `VV` 时也会得到不同向量：

```text
NN + 当前词是手机
NN + 前一个词是我的

VV + 当前词是手机
VV + 前一个词是我的
```

可以把它类比为：

```text
特征空间 = 全班共用的答题卡格式
特征向量 = 某一次作答时具体涂黑了哪些格子
权重向量 = 每个格子能够贡献多少分
```

> [!summary] 当前理解
> 特征空间由整个训练集建立并被所有样本共用；特征向量则是在这个固定空间中，对“句子、位置、候选词性”这一具体预测情况的稀疏表示。

Perceptron 的学习方式很直接：预测错误时，奖励正确词性的证据，惩罚错误词性的证据。它不需要计算概率，也不需要求梯度，却能通过不断犯错和修正逐渐学到分类边界。普通 Perceptron 的权重会随最后几个样本发生波动，这次开发集准确率先升后降，让我真正理解了为什么要引入 Averaged Perceptron。

这次最大的收获不只是写出了一个词性标注程序，而是第一次认真追问“数学公式和代码到底如何一一对应”。以前看到程序能运行、准确率会上升，可能就会认为已经实现正确；现在我意识到，科研代码最危险的情况不是报错，而是它顺利运行，却实现了另一个自己没有意识到的模型。

关于 AI，我不需要在代码生成速度上超过它。更重要的是，我要能提出问题、检查假设、验证实现、解释结果，并在想法变化时控制代码如何变化。以后可以让 AI 帮我更快地到达第一版，但最终需要由我判断这份实现是否忠实表达了研究想法。

> 一句话记忆：线性模型用稀疏特征投票，Perceptron 用错误修正权重；AI 可以帮我写代码，但公式、实现和实验结论之间的对应关系必须由我掌握。
