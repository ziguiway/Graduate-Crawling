# 作业 1：分字

> [!summary] 一句话任务
> 给定 UTF-8 编码的中文文本文件，把每个"字"（字符）切出来，字符间用空格隔开输出。
> 本质：==理解 UTF-8 编码规则，手动按字节切分多字节字符==。
## 题目要求

- **输入**：`Sentence.txt`（UTF-8 编码，可能带 BOM）
- **输出**：每个字符之间用空格隔开
- **语言**：C/C++
- **数据**：[文件:Sentence.txt](http://hlt.suda.edu.cn/index.php/%E6%96%87%E4%BB%B6:Sentence.txt)

## 核心知识点 1：UTF-8 编码规则

UTF-8 是**变长编码**：一个 Unicode 字符用 1–4 个字节表示。**首字节的高位连续 1 的个数 = 这个字符占几个字节**，后续字节都以 `10` 开头（称为 continuation byte）。

| 字节数 | 首字节格式 | 后续字节 | Unicode 范围 | 例子 |
|---|---|---|---|---|
| 1 | `0xxxxxxx` | 无 | U+0000 ~ U+007F | ASCII（`A`=0x41） |
| 2 | `110xxxxx` | 1 个 `10xxxxxx` | U+0080 ~ U+07FF | 拉丁扩展、希腊字母 |
| 3 | `1110xxxx` | 2 个 `10xxxxxx` | U+0800 ~ U+FFFF | **中文常用字**（`戴`=E6 88 B4） |
| 4 | `11110xxx` | 3 个 `10xxxxxx` | U+10000 ~ U+10FFFF | emoji、生僻字 |

> [!note] RFC 3629（2003）
> 早期 UTF-8 规范允许 5–6 字节编码，RFC 3629 已废除，**只用考虑 1–4 字节**。

### 为什么中文是 3 字节？

常用汉字 Unicode 码点在 U+4E00 ~ U+9FFF 之间（属于 U+0800 ~ U+FFFF 区间），所以用 3 字节编码。验证：

- `戴` 的字节是 `E6 88 B4`
- `E6` = `1110 0110` → 首字节，3 个连续 1 → 3 字节字符 ✓
- `88` = `1000 1000` → continuation byte ✓
- `B4` = `1011 0100` → continuation byte ✓

### 首字节高位 1 的个数判断法

```
0xxxxxxx   → 0 个 1 → 1 字节（ASCII）
110xxxxx   → 2 个 1 → 2 字节
1110xxxx   → 3 个 1 → 3 字节
11110xxx   → 4 个 1 → 4 字节
```

这是我代码里 `scan()` 函数的核心逻辑：数首字节高位连续 1 的个数。

## 核心知识点 2：C 文件 I/O

### 基本流程

```c
FILE *fp = fopen(path, mode);   // 打开
if (fp == NULL) { /* 失败处理 */ }
int ch = fgetc(fp);              // 读一个字节
fwrite(buf, 1, n, fp);           // 写 n 个字节
fclose(fp);                      // 关闭
```

### 关键 API

#### `fgetc(fp)` —— 读一个字节

```c
int fgetc(FILE *fp);
```

- 返回 `int` 不是 `char`：因为要能区分"读到的字节值 0xFF"和"读到文件末尾"。
- 文件结束或出错返回 `EOF`（通常是 -1）。
- 把返回值赋给 `char` 会丢失 EOF 检测能力（`char` 可能是 unsigned，0xFF != -1）。

#### `fputc(ch, fp)` —— 写一个字节

```c
int fputc(int ch, FILE *fp);
```

- `ch` 会被截断成 `unsigned char` 再写入。
- 我代码里用它写分隔符：`fputc('*', fp_out)`。

#### `fwrite(ptr, size, nmemb, fp)` —— 写一段字节

```c
size_t fwrite(const void *ptr, size_t size, size_t nmemb, FILE *fp);
```

| 参数 | 含义 |
|---|---|
| `ptr` | 数据指针 |
| `size` | 每个元素几字节 |
| `nmemb` | 写几个元素 |
| `fp` | 目标文件 |

返回**实际写入的元素个数**（不是字节数）。

我代码里：`fwrite(char_bytes, 1, char_len, fp_out)` —— 写 `char_len` 个字节，每个元素 1 字节。

> [!tip] fwrite vs fprintf vs fputc
> - `fputc('*', fp)` → 写单个字符
> - `fprintf(fp, "%d", x)` → 格式化写
> - `fwrite(buf, 1, n, fp)` → 写原始字节，**不解释内容**，专用于二进制 / 字节流

#### `ungetc(ch, fp)` —— 把一个字节"退回"输入流

```c
int ungetc(int ch, FILE *fp);
```

- 把 `ch` 退回到 `fp` 的缓冲区前面，下一次 `fgetc` 会重新读到它。
- 用于"先读一字节看是什么，再决定怎么处理"的情景。
- 只保证能退回 1 个字节（多次 `ungetc` 不一定都成功）。

我代码里用 `ungetc` 处理 BOM：

```c
int b1 = fgetc(fp), b2 = fgetc(fp), b3 = fgetc(fp);
if (!(b1 == 0xEF && b2 == 0xBB && b3 == 0xBF)) {
    ungetc(b3, fp);   // 不是 BOM，3 个字节都退回
    ungetc(b2, fp);
    ungetc(b1, fp);
}
```

### 文件打开模式

| 模式 | 含义 | 文件不存在时 |
|---|---|---|
| `"r"` | 只读 | 失败（返回 NULL） |
| `"w"` | 只写，**覆盖** | 创建新文件 |
| `"a"` | 只写，**追加** | 创建新文件 |
| `"rb"` / `"wb"` / `"ab"` | 二进制模式 | 同上 |
| `"r+"` / `"w+"` / `"a+"` | 读写 | 同上 |

> [!warning] `"a"` vs `"w"` 的坑
> - `"a"` 追加：每次跑程序都往旧文件后面加，跑 3 次就有 3 份重复内容。
> - `"w"` 覆盖：每次跑都是干净结果。
> 调试阶段用 `"w"`，避免重复数据干扰判断。

## 核心知识点 3：UTF-8 BOM

BOM = Byte Order Mark（字节顺序标记）。

| 编码        | BOM 字节     | 说明                     |
| --------- | ---------- | ---------------------- |
| UTF-8     | `EF BB BF` | 标识"这是 UTF-8 文件"，无字节序意义 |
| UTF-16 BE | `FE FF`    | 大端序                    |
| UTF-16 LE | `FF FE`    | 小端序                    |

UTF-8 的 BOM **可有可无**（因为 UTF-8 是字节流，没有字节序问题）。但有些编辑器（如 Windows 记事本）保存 UTF-8 时会自动加 BOM。

> [!warning] 李老师主页的说明有个小混淆
> 李老师主页写的 `0xFE 0xFF` / `0xFF 0xFE` 实际是 **UTF-16** 的 BOM，UTF-8 的 BOM 是 `EF BB BF`。本质都一样：开头有标记字节，删掉即可。

### 处理方法

读文件开头 3 字节，是 `EF BB BF` 就跳过；不是就 `ungetc` 退回。

### 不处理会怎样？

BOM `EF` 会被当成 3 字节汉字的首字节，跟着读 2 个 continuation byte，输出一个看不见的乱码字符。

## 我踩过的坑（按修复顺序）

### 坑 1：`skip_count = scan(bits)` 少减了 1

**错误代码**：
```c
skip_count = scan(bits);   // scan 返回字符总字节数
```

**问题**：`scan` 返回的是"本字符共几个字节"，但首字节已经读过了，`skip_count` 应该是"接下来还要跳过几个 continuation byte"。

**正确**：
```c
skip_count = scan(bits) - 1;   // 首字节已读
```

**症状**：ASCII 字符（1 字节）被设 `skip_count=1`，导致下一个字符被无条件吞掉。

> [!lesson] 一句话记忆
> `scan` 返回"本字符共几个字节"，不是"还要跳几个"。首字节已读，要减 1。

### 坑 2：`skip_count + continue` 的控制流根本写不对

尝试用 `while + skip_count + continue` 跳过 continuation byte，但：

- `continue` 会跳过底部输出逻辑，攒好的字节永远不输出
- continuation byte 被当成新字符首字节处理，解码链条乱掉

**改法**：去掉 `skip_count` 和 `continue`，改成**主动读** continuation byte：

```c
char_bytes[0] = ch;   // 首字节
for (int i = 1; i < char_len; i++) {
    int cb = fgetc(fp);
    if (cb == EOF) break;
    char_bytes[i] = cb;
}
// 现在 char_bytes[0..char_len-1] 是完整字符，直接输出
```

> [!lesson] 一句话记忆
> continuation byte 不是"跳过"，而是"读完攒起来一起输出"。用 `for` 主动读，不要用 `continue` 跳。

### 坑 3：`char_len` 在 `main` 里重复定义

```c
int char_len = 0;              // 第 50 行，外层
while (...) {
    int char_len = scan(bits); // 第 59 行，又定义一个内层 char_len
    ...
}
```

编译警告 `unused variable` 就是说外层那个从没被用过。内层 `char_len` 离开 `while` 循环体就销毁，状态丢失。

> [!lesson] 一句话记忆
> 同名变量嵌套作用域时，内层会"遮蔽"外层。如果不需要遮蔽，就别重复声明。

### 坑 4：`int char_bytes[4]` + `printf("%d")` 输出数字而非字符

**错误**：
```c
int char_bytes[4];
printf("%d ", char_bytes[i]);   // 输出 228 184 180
```

**问题**：题目要求输出"字符"，不是"字节的十进制数字"。

**正确**：
```c
unsigned char char_bytes[4];
putchar(char_bytes[i]);          // 输出 "戴"
```

> [!lesson] 一句话记忆
> 存字节用 `unsigned char`，输出字符用 `putchar`，不要用 `int` + `%d`。

### 坑 5：每字符 `fopen`/`fclose` 一次输出文件

**错误**：
```c
while (...) {
    FILE *fp_out = fopen(..., "ab");   // 循环里开
    fwrite(...);
    fclose(fp_out);                    // 循环里关
}
```

**问题**：33333 个字符 = 33333 次 `fopen` + `fclose`，慢且没意义；`"ab"` 追加模式还会导致跑多次后文件越来越长。

**正确**：
```c
FILE *fp_out = fopen(..., "wb");   // 循环外开一次
while (...) {
    fwrite(...);
}
fclose(fp_out);                    // 循环外关一次
```

> [!lesson] 一句话记忆
> 文件开关节流：循环外开一次，循环里只写，循环外关一次。模式选 `"wb"`（覆盖）而不是 `"ab"`（追加），避免重复数据。

## 最终代码结构

```c
#include <stdio.h>
#include <stdlib.h>

// 把字节展开成 8 位二进制（高位在前）
void byte_to_bits(int ch, int bits[8]) {
    for (int i = 7; i >= 0; i--)
        bits[7 - i] = (ch >> i) & 1;
}

// 数首字节高位连续 1 的个数 = 字符字节数
int scan(int bits[8]) {
    int count = 1;
    for (int i = 0; i < 7; i++) {
        if (bits[i] == 1 && bits[i+1] == 1) count++;
        else break;
    }
    return count;
}

int main() {
    FILE *fp = fopen("./data/Sentence.txt", "rb");
    if (fp == NULL) { fprintf(stderr, "Error\n"); return 1; }

    // 处理 BOM
    int b1 = fgetc(fp), b2 = fgetc(fp), b3 = fgetc(fp);
    if (!(b1 == 0xEF && b2 == 0xBB && b3 == 0xBF)) {
        ungetc(b3, fp); ungetc(b2, fp); ungetc(b1, fp);
    }

    // 输出文件循环外开一次
    FILE *fp_out = fopen("./data/Sentence_split.txt", "wb");

    int ch;
    unsigned char char_bytes[4];
    int char_len;

    while ((ch = fgetc(fp)) != EOF) {
        int bits[8];
        byte_to_bits(ch, bits);
        char_len = scan(bits);

        char_bytes[0] = (unsigned char)ch;
        for (int i = 1; i < char_len; i++) {
            int cb = fgetc(fp);
            if (cb == EOF) break;
            char_bytes[i] = (unsigned char)cb;
        }

        // 输出到屏幕 + 文件
        for (int i = 0; i < char_len; i++) putchar(char_bytes[i]);
        putchar(' ');
        fwrite(char_bytes, 1, char_len, fp_out);
        fputc(' ', fp_out);
    }

    fclose(fp);
    fclose(fp_out);
    return 0;
}
```

## 验证结果

- 编译：`clang -std=c11 -Wall split.c -o split`，无 warning
- 切出 **33332** 个字符，与原文件 UTF-8 字符数一致
- 输出文件 `Sentence_split.txt` 每个字符后跟一个空格，格式正确

## 我的理解

这次作业表面上是"切汉字"，真正学到的东西比想象的多：

1. **编码不是抽象概念，是字节级的事实**。以前看 UTF-8 也就是知道"中文 3 字节"，从来没自己用位运算数过首字节的 1。自己写一遍 `scan` 之后，"高位连续 1 的个数 = 字节数"这句话从知识变成了能直接用出来的工具。
2. **C 的文件 I/O 比 Python 麻烦但更透明**。Python 一行 `list(s)` 就切完了，但完全屏蔽了"字节"这个层次。C 强迫我处理 `fgetc` 返回 `int`、`EOF` 判断、`unsigned char` vs `char`、`ungetc` 退回这些细节。这些细节正是理解"计算机怎么存汉字"的关键。
3. **`continue` 不是万能跳过**。我一开始想用 `skip_count + continue` 跳过 continuation byte，结果把整个输出链条打断。教训：要"攒齐再输出"的逻辑，老老实实用 `for` 循环主动读，不要用 `continue` 跳。
4. **李老师说"不要直接看别人代码"是对的**。这套练习如果直接抄 `split_fixed.c`，我永远不会撞上坑 2 和坑 3，也就不会真正理解控制流为什么这么写。撞过坑、调试过、改对过，这个知识才是我的。
