# split.c 代码审查

> 审查对象：`split.c`（你最初写的版本）
> 审查时间：2026-07-16
> 数据文件：`data/Sentence.txt`（UTF-8 编码，无 BOM，100326 字节，33332 个字符）
> 对照版本：`split_fixed.c`（修好 3 个 bug 的版本，保留 `byte_to_bits` 和 `scan` 不变）

## 总体评价

**核心思路是对的**：用首字节高位连续 1 的个数判断该字符占几个字节 —— 这正是 UTF-8 编码规则的本质。`byte_to_bits` 和 `scan` 两个函数的实现没有问题。

但 `main` 里有 **3 个 bug**，其中 1 个是致命的（导致 ASCII 字符被无条件吞掉），还有 1 个让最终输出无法通过验收。

---

## Bug 1（致命）：`skip_count` 语义错位，ASCII 字符被吞掉

### 现象

`Sentence.txt` 里其实有大量 ASCII 字符（数字、标点、换行符 `\n`）。原程序跑下来，**每个 ASCII 字符的下一个字符都会被无条件跳过**，导致输出严重残缺。

### 根因

`scan()` 返回值的语义是"**本字符占几个字节**"：

| 首字节形式 | `scan` 返回 | 字符占用 |
|---|---|---|
| `0xxxxxxx`（ASCII） | 1 | 1 字节 |
| `110xxxxx` | 2 | 2 字节 |
| `1110xxxx` | 3 | 3 字节 |
| `11110xxx` | 4 | 4 字节 |

但 `main` 里直接用：

```c
skip_count = scan(bits);   // 第 68 行
```

`skip_count` 在第 51–55 行被当作"**接下来还要跳过几个字节**"来用：

```c
if(skip_count > 0)
{
    skip_count--;
    continue;
}
```

对 ASCII 字符：`scan` 返回 1，`skip_count = 1`，下一轮循环 `skip_count > 0` 成立，`skip_count--` 变 0，`continue` —— **下一个字节被无条件吞掉，不打印也不处理**。

### 正确语义

`skip_count` 应该表示"**首字节之后还要读几个 continuation byte**"，所以：

```c
skip_count = scan(bits) - 1;   // 首字节已读，还要读 total-1 个
```

这样：
- ASCII（1 字节）：`skip_count = 0`，不跳，直接处理下一个首字节
- 2 字节汉字：`skip_count = 1`，跳过 1 个 continuation byte
- 3 字节汉字：`skip_count = 2`，跳过 2 个 continuation byte

### 一句话记忆

> `scan` 返回的是"本字符共几个字节"，不是"接下来还要跳几个"。首字节已经读过了，要减 1。

## Bug 2：UTF-8 BOM 没处理

### 现象

如果 `Sentence.txt` 开头有 BOM（`0xEF 0xBB 0xBF`），原程序会把 `0xEF` 当成 3 字节字符的首字节处理，跟着读 2 个 continuation byte，**输出一个乱码字符**。

### 李老师主页的原话

> 同学们处理 UTF8编码的文件时，最开始可能会有两个特殊字节，即BOM（字节顺序标记），0xFE 0xFF 表示大字节序（Big-Endian），0xFF 0xFE 表示小字节序（Little-Endian）。通常来讲，只需要把这两个特殊字节删除即可。

（注：李老师主页写的 BOM 字节 `0xFE 0xFF` / `0xFF 0xFE` 实际是 UTF-16 的 BOM；UTF-8 的 BOM 是 `0xEF 0xBB 0xBF`。本质一样：开头有标记字节，删掉即可。）

### 当前数据情况

`hexdump` 验证 `Sentence.txt` 前 20 字节为 `e688 b4e7 9bb8 ...`，**没有 BOM**，所以原程序在这个数据上不会触发 bug 2。但只要换一份带 BOM 的 UTF-8 文件就会炸，必须处理。

### 修法

```c
int b1 = fgetc(fp), b2 = fgetc(fp), b3 = fgetc(fp);
if (!(b1 == 0xEF && b2 == 0xBB && b3 == 0xBF)) {
    // 不是 BOM，退回这 3 个字节
    ungetc(b3, fp);
    ungetc(b2, fp);
    ungetc(b1, fp);
}
```

### 一句话记忆

> 读 UTF-8 文件先尝 3 字节，是 `EF BB BF` 就丢掉，不是就 `ungetc` 退回。

## Bug 3：输出不符合验收要求

### 现象

原程序的 `stdout` 全是这种内容：

```
*00110011
skip_count: 1
====================================
*01100100
skip_count: 1
====================================
```

李老师的题目要求是：

> 给定文件，将文件中的句子按照字（字符）切分，**字符中间用空格隔开**。

即验收时要看到：

```
戴 相 龙 说 中 国 经 济 发 展 为 亚 洲 作 出 积 极 贡 献
```

而不是 bit 串和 `*` 标记。

### 修法

把**调试信息**和**最终切分结果**分开走两个流：

- 调试信息（bit 串、skip_count、分隔线）→ `fprintf(stderr, ...)`
- 最终切分结果（每个完整字符的字节，后跟一个空格）→ `putchar` / `printf` 到 `stdout`

这样运行时 `2>/dev/null` 就能拿到干净的切分结果，不丢调试信息。

### 一句话记忆

> 调试走 `stderr`，结果走 `stdout`，验收时 `2>/dev/null` 一屏蔽就干净了。

## 附：还有一个潜在小问题（不影响正确性）

`scan` 函数里 `count` 初值是 1，循环条件 `i < 7`，理论上最多数到 `bits[0..6]` 7 个连续 1，`count` 最大 8。但 UTF-8 首字节最多 4 个连续 1（`11110xxx`），所以实际不会触发上限 bug。代码读起来 `count` 上限是 8 容易误导，建议加一行注释说明"RFC 3629 废除了 5-6 字节，只用考虑 1-4"。

## 验证

修复版 `split_fixed.c` 在 `Sentence.txt` 上的运行结果：

- 切分输出干净，每个汉字 / 标点 / 数字之间空格隔开
- 切出 **33332** 个字符，与原文件 UTF-8 字符数一致
